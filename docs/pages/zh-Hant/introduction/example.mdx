# 代金券實際示例

本示例跟隨一張代金券經歷發行、資金池交換、兌付出示、履約和核銷的完整過程。它用於說明各方角色，並不承諾任何特定代金券、資金池、路徑或結果一定可用。

相關定義見 [概念和術語](/zh-Hant/introduction/concepts)。

## 1. 發行方公佈一項承諾

假設一家社群廚房建立了數字餐券。發行前，廚房會公佈持有人作出知情決定所需的資訊：

- 廚房的身份和聯絡方式；
- 一張代金券代表的餐食或其他商品或服務專案；
- 供應量、單位、標示價值以及廚房的履約能力；
- 可以出示代金券的地點和時間；
- 到期日、預約流程、費用、稅費或轉讓限制；以及
- 兌付出示、履約、投訴、退款、替代方案和其他補救措施如何運作。

廚房是發行方。它必須確保這些資訊準確，不得超出合理能力發行代金券，並按照持有人取得代金券時適用的條款履行承諾。建立代幣或釋出商品或服務專案，不能證明廚房具備相應能力，也不會使 GEF 成為發行方。

## 2. 資金池管理者准入代金券

一個關注糧食安全的承諾資金池會審查廚房、代金券條款和資金池自身目的。如果代金券獲准進入，資金池管理者會公佈適用規則，包括：

- 誰對資金池負責；
- 當前 `SwapPool` 所有者、代理管理員和重要依賴項的控制者；
- 接受哪些資產；
- 匯率或報價方法；
- 代幣餘額上限，即應用中所稱的 **“信用額度”**；
- 資金池費用和協議費；
- 庫存以及提取流動性的許可權；以及
- 任何另行提供資金的保證、儲備或支援安排。

准入只表示資金池配置的規則允許使用該代金券。它不能證明發行方具有履約能力，不會確定現金價值，也不會自動形成保險。

## 3. 參與者提供庫存

支持者按照適用的已公佈條款，把餐券或另一項受支援資產轉入 `SwapPool`。這筆存入會增加可用庫存。

該轉移不會自動產生資金池份額、償還請求權、提取權、獎勵或治理權。任何此類權利都必須來自另行披露的安排。

## 4. 持有人進行資金池交換

持有人透過資金池，把一種受支援資產換成餐券。介面顯示的報價是已配置報價器生成的交易引數，並不能證明餐券的現金價值或廚房的履約情況。

直接資金池交換透過轉移輸入資產、輸出資產、資金池費用和任何額外協議費在鏈上結算。它不會自動構成貸款、發行方兌付或現實世界的履約。

## 5. 持有人出示代金券

在當前應用中，選擇 **“兌付”** 會開啟普通傳送流程，並預先填入代幣所有者的地址。把代金券傳送回去可以作為向發行方出示兌付的證據；這本身不能證明廚房已經提供餐食。

廚房核實出示情況，並按照已公佈的條款提供所承諾的餐食。

## 6. 發行方記錄履約與核銷

提供餐食後，發行方會記錄已經履約的代金券單位，防止它們被重複出示。根據已公佈的流程，這可能包括接收、銷燬、取消或以其他方式停用已退回的代金券。

如果廚房沒有履行承諾，持有人應使用發行方公佈的投訴或補救流程，並行使適用法律提供的權利。應用展示了代金券，或資金池支援了交換，並不會因此使 GEF 或資金池管理者成為兌付方。

應用中的 **“停用代金券”** 是另一項操作：它會隱藏目錄上架，但餘額和歷史記錄仍然存在，管理員也可以恢復上架。它不等於履約、核銷、銷燬或取消。

## 職責一覽

- **發行方：** 說明並履行代金券承諾，記錄核銷。
- **資金池管理者：** 公佈並管理資金池的規則、匯率、費用、限制、控制措施以及明確承擔的任何保證。
- **持有人：** 審查發行方、代金券條款、資金池規則、報價、錢包授權和適用法律。
- **技術控制者：** 僅行使分配給他們的合約、依賴項、升級、目錄或費用許可權。
- **GEF：** 按照 [服務條款](/zh-Hant/governance/terms) 運營 CLC App 和配套基礎設施；它不會自動承擔上述其他角色。

## 未來的信貸安排

未來，某個資金池或其他責任方可以另行把一項交易作為可償還預付款、有擔保交易或其他信貸產品提供。此類產品需要另行提供補充條款和交易條款，明確當事方、金額、到期日、費用或利息、抵押品處理、轉讓、違約、補救措施和核銷證據。

普通傳送、資金池存入、資金池交換、兌付出示、履約或核銷，本身不會產生這些義務。
