# 代金券實際示例

本示例跟隨一項商品或服務專案和一條需求，經歷由兩個資金池組成的路徑兌換、兌付出示、履約和核銷。它說明各方角色，但不承諾任何特定代金券、資金池、路徑或結果一定可用。

相關定義見 [概念和術語](/zh-Hant/introduction/concepts)。

## 1. 發行方公佈一項承諾

假設一家社群廚房建立了數字餐券。發行前，廚房會公佈持有人作出知情決定所需的資訊：

- 廚房的身份和聯絡方式；
- 一張代金券代表的餐食或其他商品或服務專案；
- 供應量、單位、標示價值以及廚房的履約能力；
- 可以出示代金券的地點和時間；
- 到期日、預約流程、費用、稅費或轉讓限制；以及
- 兌付出示、履約、投訴、退款、替代方案和其他補救措施如何運作。

廚房是發行方。它必須確保這些資訊準確，不得超出合理能力發行代金券，並按照持有人取得代金券時適用的條款履行承諾。建立代幣或釋出商品或服務專案，不能證明廚房具備相應能力，也不會使 GEF 成為發行方。

廚房還會發布一條**商品或服務專案**，說明可提供的餐食。代金券和商品或服務專案相互關聯，但並不相同：代金券代表可兌付的承諾；商品或服務專案幫助人們發現相關商品或服務。

## 2. 參與者釋出一條需求

附近一所學校持有交通代金券，並需要為一場活動準備餐食。學校釋出一條**需求**，說明餐食、數量、地點、時間和聯絡方式。

需求只表達需要。它不會自動接受廚房的代金券、預訂餐食、形成合約、授權兌換，也不承諾學校一定繼續。學校仍需核查廚房、代金券條款、可用路徑、報價和適用條件。

## 3. 獨立的資金池管理者維護一條路徑

兩個獨立治理的資金池把資產連線起來：

1. 一個出行資金池准入學校的交通代金券和玉米代金券；以及
2. 一個糧食安全資金池准入玉米代金券和廚房的餐券。

每位資金池管理者稽核資產並公佈該資金池的規則，包括：

- 誰對資金池負責；
- 現在的 `SwapPool` 所有者,代理管理員和物質依賴控制器;
- 已接受的憑證和其他支援資產;
- 匯率或報價方法;
- 代幣餘額上限，應用中稱為**“信用額度”**；
- 池和協議費用;
- 庫存和流動性提取權力;以及
- 任何單獨資助的擔保,儲備或支援安排.

准入意味著一個池的配置規則允許使用券. 它不證明履行能力,建立現金價值,建立保險或使兩個池成為一個受監管實體.

## 4. 參與者提供庫存

出行資金池持有可以換取交通代金券的玉米代金券。糧食安全資金池持有可以用玉米代金券換取的餐券。參與者可能根據不同的公開安排提供了這些庫存。

存款增加了可用的池庫存,但它不會自動建立一個池股份,還款要求,撤回權,獎勵或治理權. 任何這樣的權利必須來自一個單獨披露的安排.

## 5. 應用發現路徑並生成報價

學校的錢包開啟**可存入**檢視並選擇餐券。CLC Core 估算一條可能的路徑：

`transport voucher → mobility Pool → maize voucher → food-security Pool → meal voucher`

這一發現結果並不保證兌換成功。每一跳都取決於當前准入、資金池代幣餘額上限、可用庫存、報價和費用配置、受支援的代幣行為以及服務資料是否新鮮。

學校選擇希望獲取或花費的金額。CLC Core 隨後在同一個固定區塊讀取兩個資金池，生成有時間限制的權威報價，並模擬整個錢包批次。應用的**路徑詳情**會顯示兩次兌換、估算金額，以及每一跳的資金池費用和協議費用。

## 6. 持有人執行路徑兌換

核對最低收到金額和報價截止時間後，學校選擇**確認兌換**並簽署準備好的批次。應用會提交一筆同鏈交易，其中包含每個資金池的授權和有明確限制的兌換呼叫。

如果任何呼叫失敗，整筆交易都會回滾；第一筆資金池兌換不會在第二筆失敗後仍保留為已結算。成功時，學校的分組收據會顯示跟蹤 ID、交易雜湊、兩個資金池跳、已結算金額和每一跳的費用。

學校現在持有餐券。鏈上兌換屬於**兌換結算**。它讓學校獲得餐券條款所描述的權利，但不能證明廚房已經提供餐食。

## 7. 持有人呈現憑證

在當前應用中，選擇**兌付**會開啟普通傳送流程，並預先填入代幣所有者地址。把代金券送回是向發行方出示的證據；這本身不能證明廚房已經提供餐食。

學校遵循廚房的預訂或聯絡流程. 廚房會根據公佈的條款, 驗證選單並提供承諾的餐點.

## 8. 發行方記錄履約和核銷

提供餐後,廚房記錄完成的單位,所以他們不能提出兩次. 根據公佈的流程,這可能涉及收到,燒燬,取消或以其他方式停用返回的優惠券.

如果廚房不履行承諾，持有人可以使用發行方公佈的投訴或補救流程，以及適用法律提供的任何權利。不能僅因 App 發現了路徑或資金池支援兌換，就把 GEF 或資金池管理者視為兌付責任方。

在應用中選擇**“停用代金券”**是另一項操作：它會隱藏目錄條目，但餘額和歷史記錄仍會保留，管理員可以恢復上架。它不等於履約、核銷、銷燬或取消。

## 職責一覽

- **發行方：** 說明並履行代金券承諾，記錄核銷。
- **需求釋出者：** 說明需要，但不會自動接受代金券或路徑。
- **資金池管理者：** 分別公佈和管理每個資金池的規則、匯率、費用、限制、控制，以及明確承擔的任何擔保。
- **持有人：** 核查發行方、代金券條款、資金池、路徑報價、費用、錢包授權和適用法律。
- **CLC App 和 CLC Core：** 查詢可能路徑並生成報價，準備和中繼已簽署批次，並彙總技術結算記錄。它們不能證明發行方已經履約。
- **技術控制者：** 僅行使分配給他們的合約、依賴項、升級、目錄、路徑服務或費用許可權。
- **GEF：** 按照 [服務條款](/zh-Hant/governance/terms) 運營 CLC App 和配套基礎設施；它不會自動承擔上述其他角色。

## 路徑不可用時

應用可能找不到路徑，或因以下原因無法生成報價：庫存不足；會超過資金池上限；代金券未獲准入；代幣或報價器不受支援；錢包缺少足夠輸入；路徑資料已過時；或最終批次模擬失敗。資金池狀態變化時，報價也可能在提交前過期或失效。

這一結果不會改變需求、商品或服務專案，也不會改變發行方現有的代金券義務。參與者可以重新整理路徑、選擇較小金額、使用另一種符合條件的輸入代金券，或等待資金池狀態變化。

## 未來的信貸安排

未來，某個資金池或其他責任方可以另行把一項交易作為可償還預付款、有擔保交易或其他信貸產品提供。此類產品需要另行提供補充條款和交易條款，明確當事方、金額、到期日、費用或利息、抵押品處理、轉讓、違約、補救措施和核銷證據。

普通傳送、資金池存入、直接或路徑資金池兌換、代金券兌付出示、履約或核銷，本身都不會產生這些義務。
