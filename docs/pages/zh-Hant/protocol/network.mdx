# 協議網路架構

多個獨立治理的資金池可以把您持有的代金券連接到想要的代金券。每個資金池按照自己的規則，使用可用庫存完成交換中的一步。

[CLC 軟體路由參考](https://software.cosmolocal.credit/contracts/routing)是路線發現、資格、執行和服務介面的權威來源。軟體文件目前提供英文版本。本頁說明參與者的操作流程和責任。

## 生產路徑發現與執行

在 App 的 **可存入（Credit）** 檢視中，選擇想要 **取得（Get）** 或 **花費（Spend）** 的代金券。例如，某條路線可以透過兩個不同的資金池，把交通代金券換成食品代金券。

找到連接並不保證可以交換。受支援的代金券、資金池限額、可用庫存、費用、錢包相容性和服務可用性，都必須允許所請求的數量。

### 權威報價

確認前請查看 **路徑詳情（Route details）**：您支付什麼、收到什麼、每個參與的資金池、費用、最低收到數量和報價到期時間。估算幫助您探索選項；報價才是您授權的交易提案。報價到期或資金池條件改變時，應重新取得報價。

[路由參考](https://software.cosmolocal.credit/contracts/routing)和[服務配置](https://software.cosmolocal.credit/core-api/configuration#credit-router)維護技術資格規則和報價設定。

### 已簽署的原子批次

您審核並授權完整交換。當前路線要麼整體成功，要麼在某一步失敗時，把所有資金池交換一起還原。這樣可避免僅完成部分路線，但不能保證之後一定交付商品或服務。

交易構建和執行方法，見[執行路線](https://software.cosmolocal.credit/contracts/routing#execute-a-route)。

### Solidity `SwapRouter` 與費用

僅提供報價的 Solidity `SwapRouter` 與 App 的交換流程是不同的軟體元件。二者的關係見[路由](https://software.cosmolocal.credit/contracts/routing)。

對參與者而言，重要的是檢查完整報價。每個資金池都可能收費。共享路線不會合併資金池，也不會使某個管理者對另一個資金池負責。

### 收據與失敗狀態

提交後，請檢查交換是待處理、已確認還是失敗，並保留收據。找不到路線時，可以嘗試重新整理、減少數量或選擇另一種受支援的輸入代金券。

交換失敗不會改變發行方已有的承諾。交換成功會記錄餘額變化；履約和核銷仍按照發行方條款處理。請參閱[實用示例](/zh-Hant/introduction/example)。

開發者可在 [CLC Core API 參考](https://software.cosmolocal.credit/core-api/reference)中查閱交易和追蹤介面。

## 資金池內部結構

依賴資金池之前，請確定管理者、合約所有者、升級權限方、費用接收方，以及誰能更改重要設定。技術控制者與負有責任的管理者可能是不同的主體。

軟體參考文件維護[資金池機制](https://software.cosmolocal.credit/contracts/pools)和[部署驗證](https://software.cosmolocal.credit/contracts/deployments)。本文件說明[角色與詞彙](/zh-Hant/introduction/concepts)、[治理責任](/zh-Hant/governance/mechanics)和[更廣泛的 CPP 設計](/zh-Hant/white-paper)。
