## **11. 治理機制**

本章提出了治理模板.它並不代表當前的 CLC App 使用治理代幣投票,時間鎖定,共享保險,索賠流程或下面描述的所有控制.每個部署都需要確定其實際決策者,當局,合同,過程和政策.

- **憲法價值觀:** 人們的關懷,環境的關心,公平性,互惠,非主導性和彈性.
- **提案型別:** 費用,限額和指數變化;流動性授權;集團上市和撤銷;可選的覆蓋決策;引數保護.
- **負責的過程:** 認可可能來自管理員,合作社,公共機構,聯合會,多合夥人,連鎖投票或其他公開和負責任的結構.
- **批准門:** 按行動類進行引數,對價值指數變化,緊急權力和其他關鍵行動的門更高.
- **代表:** 提供公共任務,衝突披露和召回的可選授權.
- **電路打斷器:** 緊急暫停,有明確的標準,授權運營商,恢復條件和必要的死後檢查.
- **透明度:** 已公佈的變化和流動,附有對交換結算,發行人履行,儲備,使用限額,路由和擔保人的單獨證據.

**登記管理.** 一個CPP-相容的部署可以維護券,代幣和資金池的發現登記.授權控制器可以透過部署的披露管理過程新增,更新,暫停或刪除登錄檔輸入. 登錄檔的刪除影響了該登入的發現和路由;它不會自行刪除代幣,改變持有者的餘額,履行發行人的義務,或停用其他功能合同.

釋出的登記規則應使狀態有條件,並可能將重複不履行,欺詐或虛假陳述,不安全的合同行為或持續違反公佈原則作為暫停或刪除的理由.在可行的情況下,該過程應該提供通知,補救機會和上訴途徑.緊急刪除需要公開事件報告和自動審查或日落.

**禁止列表.** 在本模板下,登錄檔不允許:

1. 直接資助或激勵超越達成的邊界,暴力或武器化,強制採集或系統濫用的生態破壞工具;或
2. 沒有明確的表達和履行條款,責任和補救途徑.

禁止清單隻能透過採用已透過的關鍵行動門和時間限制進行編輯,公開審計和可變化,如下說明:Q3 + T3在附件D中.

### **11.1 匯率和限制治理**

**時間限制的變化.** 根據本模板的部署,只有在公開時間鎖定後才會改變匯率方法和單獨實施限制引數.緊急路徑將使用單獨披露的授權過程,幷包括自動日落或審查.

**批准門.** 該模板提出了價值指數基因變化和全球限制級別變化的更高批准門,對於特定組的第三方變化的中期門以及常規費用變化的標準門.

**釋出的資料.** 一個參與的部署將為每個組釋出連鎖指數變數,預言源或中位數,更新序列,限制窗戶和封頂以及故障模式或安全常態.

**緊急暫停的標準.** 參與部署將預示諸如神器中斷,高限度使用與履行故障或不變性故障等條件,以及恢復檢查和事故後審查要求.

**一個池和券的公共索引料示例**

- **標誌:** 例如,`Maize_50kg@IssuerY`.
- **參考單位:** 指數單位 (IUX).
- **釋出值:** 30.000 IUX.
- **來源:** 確定來源的中位數,例如當地市場調查,部署公告和部署基線.
- **更新時間:** 每天18:00 EAT,有24小時時間鎖定.
- **失效模式:** 在最後一個有效值上結,應用披露的限制政策,並在72小時停機後暫停.
- **理由:** 已公佈的備忘錄和以前更新的變化記錄.
- **簽署者:** 披露的多標籤地址和批准門.

### **11.2 擬議的保險基金操作手冊**

**只有可選的設計.** 本行本僅適用於已明確採用和資助保險基金的部署,併發布了涵蓋事件,有資格的索賠者,負責人,資產,限制,排除,證據要求,程式和管理條款.CLC App 沒有 GEF 僅因為該設計出現在白書中,就能提供覆蓋.

**可能是觸發器.** 透過的政策可能涵蓋定義發行人不履行,庫存缺陷或橋樑或保證金損失.

**評價.** 負責機構將調整交易收據,庫存餘額,擔保人債券,贖回提交記錄,發行人的響應和其他必要證據,然後釋出與隱私和法律一致的事件記錄.

**顯著的損失布.** 如果每個層都存在且合法適用,則保險可以使用: (1) 負責任發行人債券或擔保人股份 → (2) 儲備水平 → (3) 擬議的網路保險基金 → (4) 暫時降低到可選的覆蓋索賠,只有當現有條款和適用的法律明確授權它 → (5) 對被證明的欺詐或濫用行為進行合法回收.

覆蓋率調整不會減少發行人的基本券承諾或改變連鎖餘額,除非有效的現有條款和適用的法律明確允許該結果並獲得所有要求持有人同意.

**限制和排除.** 釋出的覆蓋範圍將定義上限,符合條件的呈現,證據,索賠視窗,排除路線或事件,地理限制以及處理耗盡儲備.

**顯著的恢復時間表.** 如果透過並公佈:

1. 索賠首先來自負責發行者或擔保人債券,然後從適用的庫儲存備,然後是擬議的網路保險基金;
2. 任何降低到可選的覆蓋索賠將僅限於現有覆蓋條款和適用法律授權,直到公佈的事件上限;
3. 恢復計劃可以在指定期內運用已確認的回收價值份額,之後任何剩餘的覆蓋赤字將成為公開死後的記錄損失;
4. 每個決定都會提供一個收據,其中包含事件ID,受影響的索賠和憑證,決定,恢復計劃和上訴視窗.

### **11.3 擔保框架**

根據本節,分別區分了發行人責任,可選的池保護和第三方保證.CLC App, CPP, GEF 任何更廣泛的網路都會自動保證券.

**基本發行人責任**

- 發行者承諾根據其公佈的條款提供所述商品,服務或合法的現金等價.
- 發行方將公佈誰可以提交憑證,什麼是滿足意味著,在哪裡和何時可用,需要哪些證據,以及適用的補救措施.
- 如果發行人未能履行,發行者是首要負責人. 池或網路保護只適用於單獨採用,資助和披露時.

**可選的池保護**

一個資金池管理者可以選擇將一個嚴格定義的保護新增到被錄取的憑證中.它不是自動的,並且需要在庫的元資料和適用條款中識別負責人,資金,有資格的活動,限額,窗戶,證據,排斥和補救措施.

說明性保護型別包括:

1. **儲備資產覆蓋範圍:** 經驗證的發行人未履行後,負責集團實體將以指定儲備資產支付一筆確定的金額,但須按其公佈的上限和可用資助儲備.
2. **轉換視窗:** 資格化事件後,集團提供一個限時的交換途徑進入此前或其他批准的資產,受限制和庫存約束.這是基於庫存的流動性保護,而不是承諾每個交換都是可逆的.
3. **替代性履約:** 負責人在公佈的數量或價值上限範圍內安排批准的替代供應商.
4. **匯率帶保護:** 對於選定的券類別,一組只提供在其現有條款中所述的覆蓋性調整或交換回收補救措施.這不會減少發行者的基本券義務.

**可能的資金來源**

- **發行人債券:** 發行人投放或在公開儲備中持有的抵押金,並在經過驗證的覆蓋事件後可用.
- **池儲備:** 由負責池組實體控制的資產,並分配給其宣傳的保護.
- **第三方擔保人債券:** 已確定的外部擔保人對所述發行方,代金券類別或事件的抵押金.

擔保人參與將遵循公佈的資格標準,債券規模,集中限額,決策權和法律執法規則.

**索賠程式**

透過的一項政策將定義可稽核的觸發因素,例如在有效贖回提交後錯過的履行期限,經過驗證的發行人破產性,已覆蓋的橋樑或保證券失敗或正式宣佈的事件情況.

- 參與者如何開放索賠,並提供所需的提交和履行證據;
- 驗證券條款,發行人回應和技術記錄;
- 裁決和上訴視窗;
- 授權的支付路徑,資產,上限和收據.

從發行方,仲裁或法律執法獲得的收益將根據公佈的政策重新填補適用的債券或儲備,然後用於擬議的CLC網路池交換訪問.

**要求披露資訊**

對於每個覆蓋的池和券類,負責人將公佈:

- 擔保人是否缺席,是自願的或有義務的;
- 債券或儲備規模和度上限;
- 保護型別,資產,蓋頂,窗戶和排除;
- 提交,履行,索賠和上訴的最後期限;以及
- 一個明確的宣告,說明誰能保證什麼以及什麼不能保證.

**監護原則.** 資金池管理者負責法律或治理結構為他們所宣傳的保護負責.CPP-相容的部署可能提供標準,登錄檔或可選共享政策,但沒有CLC沒有 GEF 無需提供任何資金,

### **11.4 防止治理俘獲的保障措施**

根據本模板,以下是需要採用的最高審批級別和長時間限制的關鍵行動:

1. 改變擬議的費用布,包括其覆蓋範圍和核心運營優先事項;
2. 修改法典登記庫的根;
3. 變化覆蓋範圍,索賠上限或決策權威;
4. 擴大緊急暫停許可權;或
5. 削弱在本文中所述的 Pool叉性,透明度或集團主權承諾.

### **11.5 分叉與退出程式**

如果治理被捕獲或價值大幅漂移,社群,資金池管理者和運營商可以透過斷網路治理層來尋求退出.底層池和憑證的連續性將取決於部署的合同,鑰匙,介面,基礎設施,第三方服務以及適用的義務.

退出過程可能:

1. **釋出快照:** 輸出選定的登錄檔,憑證,價值,限制和費用政策,然後釋出簽署的快照雜湊.
2. **重新部署治理服務:** 在新的負責任結構下部署新的登記根,路線服務和任何採用的費用或覆蓋模組.
3. **重新註冊:** 允許資金池管理者透過在新的根下注冊自己的池地址進行選擇,而不需要持有者遷移其他功能代金券.
4. **重新呼叫客戶:** 在 SDK 和介面中新增新的根作為可選擇的網路配置檔案,並透過披露的治理過程進行任何預設更改.
5. **管理一個橋樑時期:** 保持安全的相容路線,並拒絕違反新配置規則的路線.

設計的目標是,離開正規登錄檔不會停用其他功能的本地池.實際連續性仍然取決於部署;聯邦是一個選擇發現和協調層.
