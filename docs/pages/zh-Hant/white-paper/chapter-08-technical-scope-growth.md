## **8. 技術範圍和增長**

本章描述了可選或擬議的工作.CLC App 或 Protocol v1.1.0.

可能的工作領域包括:

- 在相容的池中執行路由,包括登錄檔,報價,限制,費用和庫存發現;
- 在原子結算不可的情況下,用於跨域執行的時間鎖定託管或HTLC介面卡;
- 小型或個人資金池的介面和政策工具;
- 可稽核的憑證,彙總,匯率方法,限額,控制者和費用登記冊表;
- 具體部署的支付提供商聯結器,現金流和資格控制;
- 複合資產與外部流動性場所的連線,用於重新平衡和支付流動性的;以及
- 透過的覆蓋範圍,運營成本或流動性授權的政策資金轉換.

外匯市場價格不會決定發行者根據券條款所欠的債務.一個集團可以對可置資產使用保護的外部參考,但其公佈的匯率方法,限制,費用和庫存將控制其報價.

### **8.1 擬議的路由服務與 SDK 規範**

**發現.** 擬議的路線服務將查詢已識別的資產錄取登記,匯率方法,限制,費用,庫存,事件和控制者資訊.快取記錄將包括新鮮度界限和來源識別符號.

**網路個人資料.** 客戶端可以支援多個登錄檔根或政策配置檔案. 它會告訴參與者哪些配置檔案,對方,介面卡,限制和負責任的服務運營商使用報價. 一條跨配置檔案路線需要滿足每個適用的跳轉條件.

**路徑政策.** 負責運營商可以排除不安全的依賴或對方,並應用路線水平上限,新鮮度要求和健康標準. 這些訊號將支援決定;它們不會保證履約或防止損失.

**費用和限制.** 一項報價將列出組費,任何額外的現行協議費和任何單獨提出的路由或服務費.執行將拒絕過期報價或違反限制.

**原子能和恢復.** 在使用HTLC或保證時,該服務將披露時間缺失,中斷路徑,負責控制者,事件程式和剩餘風險.

**擬議的批次淨化和重新平衡.** 選擇服務可能會收集重新平衡意圖並搜尋相容的迴圈或鏈.

1. 釋出可機器閱讀的收據,標識執行週期,資產,金額,估值時間和費用;
2. 執行透過的每期上限和對方政策;
3. 拒絕違反任何參與池的授權,限制或可用庫存的活動;以及
4. 儲存確定性輸入和收益用於審查和爭端處理.

**SDK要求.** 其他SDK對於執行的路線,將提供定性報價到收件對映,每站不變檢查,可理解的故障程式碼和審計友好的日誌.Protocol v1.1.0 `SwapRouter` 只有報價,而不會執行這些路線.

#### **8.1.1 最低聯盟相容性規範**

尋求跨配置路由的Pool生態系統將為:

1. **資料庫的根源:** 資產,彙總,匯率方法,限制和費用政策的識別符號或確定性解決它們的一個根.
2. **收據:** 每次跳躍的個人資料,進出資產,金額,報價來源和時間標籤,限量快照,費用,庫存結果和執行結果.
3. **執行訊號:** 關於庫存,限量利用,事件以及任何單獨證明的履行或資助保護的新鮮資訊.
4. **政策限制:** 允許或拒絕的對方,資產類別,介面卡以及任何保證金要求.
5. **失敗程式碼:** 拒絕,過期,限制,庫存,政策,依賴性或事件故障的決定性解釋.

一個配置檔案可以新增覆蓋,合規性,仲裁或其他服務,而不會使它們成為基本CPP相容性的要求.每個可選的服務都會確定其負責人,權威,範圍和條款.

### **8.2 許可,驗證和退出**

Protocol v1.1.0 合同是EVM-協議儲存庫中的合同 `src` 檔案目錄在AGPL-3.0除了已確定的未修改的第三方元件,這些元件保留了自己的條款. 發表的源頭,ABI和部署說明支援獨立審查,但本身並不能證明審計,安全部署或法律合規性.

每個部署將單獨披露其程式碼版本,構建來源,地址,控制器和升級權力,審計狀態,登錄檔映象以及任何時間鎖定或暫停保護.

擬議的 **叉子套件** 可能包括:

1. 確定性部署指令碼;
2. 登記快照和出口工具;
3. 一個為重定路線服務,SDK和介面的記錄過程到一個新的登錄檔根;
4. 一個資金池管理者安全離開共享登錄檔的檢查清單;以及
5. 一份未發行券的遷移檢查清單,包括髮行人通知,提交和履行截止日期,繼續訪問記錄以及補救措施.

當社群,合作社,公共機構,聯邦,多業務或服務運營商需要不同的治理時,相容的叉子可以提高彈性.實際連續性仍然取決於合同所有權,鑰匙,依賴性,介面,基礎設施,法律義務和第三方服務.
