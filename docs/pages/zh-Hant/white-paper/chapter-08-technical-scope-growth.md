## **8. 技術範圍和增長**

本章把當前生產路徑服務與可選或擬議擴充套件區分開來。這裡所述當前功能屬於公開 CLC App/Core 部署；它不是 Protocol v1.1.0 合約或其他部署自動具備的功能。

目前的公開部署包括:

- 基於圖的發現，用於查詢可透過相容資金池獲得的代金券；
- 為選定同鏈路徑生成權威固定區塊報價；
- 逐跳計算資金池費用、協議費用、最低輸出和截止時間；
- 完整批次模擬、參與者簽名和 Calibur 中繼執行；
- 一筆同鏈交易，任何呼叫失敗都會回滾所有路徑呼叫；以及
- 分組收據和逐跳結算事件對賬。

可能的增長領域包括:

- 在原子結算不可的情況下,用於跨域執行的時間鎖定託管或HTLC介面卡;
- 其他登錄檔或政策配置，以及跨配置路徑；
- 選擇參與庫存再平衡和批次結算;
- 小型或個人資金池的介面和政策工具;
- 可稽核的憑證,彙總,匯率方法,限額,控制者和費用登記冊表;
- 具體部署的支付提供商聯結器,現金流和資格控制;
- 複合資產與外部流動性場所的連線,用於重新平衡和支付流動性的;以及
- 透過的覆蓋範圍,運營成本或流動性授權的政策資金轉換.

外匯市場價格不會決定發行者根據券條款所欠的債務.一個集團可以對可置資產使用保護的外部參考,但其公佈的匯率方法,限制,費用和庫存將控制其報價.

### **8.1 當前路徑服務和更廣泛的規範**

**發現。** CLC Core 根據已配置目錄、登錄檔關係、資金池引數、費用、限制、餘額和鏈上事件維護經過對賬的圖。它估算會話錢包可到達的資產，並標記過時資料。公開配置最多搜尋三跳路徑。發現結果不是可執行承諾。

對於選定路徑，CLC Core 在同一個固定區塊讀取參與資金池，並重現受支援的 `SwapPool` 計算。它逐項列出資金池費用和協議費用，為每一跳設定最低輸出和截止時間，準備錢包呼叫，並模擬完整批次。不受支援的代幣、報價器、錢包或資金池條件會被拒絕。

**當前執行。** 參與者簽署一個 Calibur 批次，其中包含每一跳的 allowance 重置、allowance 授予和帶邊界的提取。中繼器提交一筆啟用 `revertOnFailure` 的同鏈交易。這為當前路徑提供交易級全有或全無行為，但不等於跨鏈原子性、HTLC 或託管路徑、自動再平衡或淨額結算。

**收據和運營。** 應用用一個跟蹤 ID 彙總路徑，並記錄交易狀態、跳轉順序、資金池、代幣對、報價和結算金額、資金池費用、協議費用和中間餘量。服務監測圖的新鮮度、路徑數量和報價結果、模擬失敗、中繼時長、對賬和糾正，以及未解決或未知的索引成員。運營遙測不能證明發行方履約。

客戶端可以支援多個登錄檔根或政策配置。它應向參與者說明報價使用的配置、交易對手、介面卡、限制和責任服務運營方。跨配置路徑必須滿足每一跳的所有適用條件。

可問責的運營方可以排除不安全的依賴項或交易對手，並應用路徑級上限、新鮮度要求和健康標準。這些訊號可以輔助決策，但不能保證履約或防止損失。

**費用和限制。** 當前報價列出每一跳的資金池費用和任何額外協議費用。公開應用目前不會另收路徑服務費。任何未來服務費都會單獨披露。執行會拒絕過期報價或違反邊界的交易。

**跨域原子性和恢復。** 如果未來路徑無法使用當前同鏈原子批次，而是使用 HTLC 或託管，服務應披露超時、中止路徑、責任控制方、事件流程和剩餘風險。

**擬議的批次淨額結算和再平衡。** 選擇加入的服務可以收集再平衡意圖，並搜尋相容的迴圈或鏈。它將：

1. 釋出機器可讀的收據，標明執行週期、資產、金額、估值時間戳和費用；
2. 執行每期採用的上限和對手政策;
3. 拒絕任何違反參與池的授權,限制或可用庫存的活動;
4. 儲存確定性輸入和收件以進行審查和糾紛處理.

**SDK 和介面要求。** 可複用的路徑整合應提供確定性的報價到收據對映、逐跳不變數檢查、易於理解的故障程式碼和便於審計的日誌。當前生產 App/Core 實現為其自身配置提供這些功能。Protocol v1.1.0 的 Solidity `SwapRouter` 仍僅用於報價，不執行路徑。

#### **8.1.1 最低聯盟相容性規範**

尋求跨配置路由的Pool生態系統將為:

1. **資料庫的根源:** 資產,彙總,匯率方法,限制和費用政策的識別符號或確定性解決它們的一個根.
2. **收據:** 每次跳躍的個人資料,進出資產,金額,報價來源和時間標籤,限量快照,費用,庫存結果和執行結果.
3. **執行訊號:** 關於庫存,限量利用,事件以及任何單獨證明的履行或資助保護的新鮮資訊.
4. **政策限制:** 允許或拒絕的對方,資產類別,介面卡以及任何保證金要求.
5. **失敗程式碼:** 拒絕,過期,限制,庫存,政策,依賴性或事件故障的決定性解釋.

一個配置檔案可以新增覆蓋,合規性,仲裁或其他服務,而不會使它們成為基本CPP相容性的要求.每個可選的服務都會確定其負責人,權威,範圍和條款.

### **8.2 許可,驗證和退出**

Protocol v1.1.0 合同是EVM-協議儲存庫中的合同 `src` 檔案目錄在AGPL-3.0除了已確定的未修改的第三方元件,這些元件保留了自己的條款. 發表的源頭,ABI和部署說明支援獨立審查,但本身並不能證明審計,安全部署或法律合規性.

每個部署將單獨披露其程式碼版本,構建來源,地址,控制器和升級權力,審計狀態,登錄檔映象以及任何時間鎖定或暫停保護.

擬議的 **叉子套件** 可能包括:

1. 確定性部署指令碼;
2. 登記快照和出口工具;
3. 一個為重定路線服務,SDK和介面的記錄過程到一個新的登錄檔根;
4. 一個資金池管理者安全離開共享登錄檔的檢查清單;以及
5. 一份未發行券的遷移檢查清單,包括髮行人通知,提交和履行截止日期,繼續訪問記錄以及補救措施.

當社群,合作社,公共機構,聯邦,多業務或服務運營商需要不同的治理時,相容的叉子可以提高彈性.實際連續性仍然取決於合同所有權,鑰匙,依賴性,介面,基礎設施,法律義務和第三方服務.
