## **執行摘要**

**承諾匯聚協議 (CPP)** 說明獨立治理的承諾資金池如何協調兌換，同時讓責任留在明確的角色中。發行方仍對其代金券承諾負責，資金池管理者仍對資金池規則負責；CLC App 和 GEF 都不是普遍擔保人。

Protocol v1.1.0 提供當前直接兌換的構建塊：`GiftableToken`、`SwapPool`、可選登錄檔和估值模組、資金池代幣餘額上限、資金池費用、額外協議費用，以及僅用於報價的 Solidity `SwapRouter`。生產環境中的 CLC App 和 CLC Core 現在可以發現經過最多三個資金池的同鏈路徑，生成固定區塊報價，模擬並準備已簽署的原子錢包批次，協調中繼，並彙總其結算記錄。這些合約仍不會記錄現實世界履約、自動建立流動性提供者份額、執行跨鏈路徑或批次淨額結算，也不會提供普遍儲備、保證或保險。

歷史性 **Sarafu Network** 它的服務後來轉向了 CLC App. 這不是一個表示每個歷史賬戶,錢包,代幣,券商,池,餘額,報告,參與者或義務遷移的表現.

**歷史 Sarafu Network 快照  C2023年7月5日至2025年7 月20日間的熱點活動**

- 285,197個同行交易所
- 188 唯一的活性 承諾資金池
- 745 唯一的活躍券

這些數字是歷史性證據,而不是當前的CLC使用資料.

更廣泛的 CLC 設計把當前路徑兌換與相容網路未來可以如何發展區分開來：

1. 把可問責的路徑服務擴充套件到其他登錄檔、政策配置和領域；
2. 協調可問責的網路服務，同時保留本地責任；
3. 支援單獨資助的流動性任務,擔保,儲備或保險政策;
4. 分別衡量資金池兌換、代金券兌付出示、履約和核銷；以及
5. 使用擬議的網路分成和單獨採納的服務費用為共享服務提供資金。

該提案包括**擬議的 CLC 治理代幣**和**擬議的 CLC 網路資金池**；兩者都不是當前 App 或 Protocol v1.1.0 的一部分。

根據擬議的模式,流動性和治理參與者只能透過單獨採用已公佈的資格,風險,控制,轉讓權,回收條款和費用規則的程式來採取行動.普通池存款不會自動創造任何股份,償還,撤銷,獎勵或治理權利.

共同目標是:

> 增加負責任的交流和履行現實承諾,同時保持關心,公平,本地責任和彈性.

防止捕獲和可靠退出仍然是設計的核心目標.擬議的控制包括時間延遲治理,多次批准門,透明委託,衝突規則,事件審查以及文件化分叉和遷移過程.這些控制將減少選定的治理風險,但無法消除損失或保證結果.
