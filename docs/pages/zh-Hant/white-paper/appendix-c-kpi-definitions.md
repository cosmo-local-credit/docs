## C. 擬議的 KPI 定義

這些關鍵指標構成了擬議的測量規範,而不是當前應用程式或協議記錄每一個所需的事件的宣告.

每個公佈的KPI都必須包含:

- 負責的出版商和資料來源;
- 事件或狀態的定義;
- 一組或測量期;
- 單位和估值方法;
- 估值時間表;
- 包容和排斥的規則;
- 部分,爭議,過期,無法訪問和糾正的記錄處理;
- 需要在鏈外的證據或證明;
- 審查歷史和資料質量限制;以及
- 結果是否在鏈上,報告,認證,獨立驗證或估計.

| KPI | 擬議的定義 | 需要的證據和排除 |
| --- | --- | --- |
| **有效的表達** | 在一段時間內接受發行人贖回過程中的計數或單元 | 報表標識,發行人,持有許可權,數量,時間,狀態;排除複製和無效的請求 |
| **履約率** | 已填寫的有效表現,分為相同成熟群體的有效呈現 | 單獨的發行方績效證據;報告開放,拒絕,爭議,部分和糾正的案件 |
| **核銷完整性** | 已填寫的表單,分為已填補的表現 | 燃燒,取消,停用記錄或與履行相關的其他未再使用證據 |
| **履約延遲** | 呈現到完成時間的中位數和90個百分點 | 不取代發行到提交或收購到提交的持有時間 |
| **持有時間** | 收購到提交時間的中位數和分佈 | 確定收購事件並排除未知的收購時間 |
| **現有資格承諾** | 已確定排除後仍然存在的可接受第三方承諾 | 發行人身份和條款;不包括適用的發行人的庫存,過期,燃燒,清理,測試和非承諾代幣 |
| **資金池交換量** | 根據一個披露的估值方法完成直接組交換的價值 | 鏈上結算事件,代幣單位,匯率來源,時間;不歸類為發行人履行 |
| **資金池庫存** | 在特定時間內,一個集團所持的衡量支援資產 | 合同餘額,費用保留,不可訪問的資產,估值方法和所有者撤銷權 |
| **儲備充足性** | 符合條件的可用儲備資產,按明確覆蓋的風險分為 | 覆蓋政策,資產資格性,保管/控制,負債,排除和估值;不包括預設的全部代幣供應 |
| **限制利用率** | 測量的庫存代幣餘額以其當前配置的上限分為 | Limiter地址,代幣,池,時間標籤,變化和無限制期限 |
| **報價透過率** | 透過有效的報價嘗試劃分成功報價回覆 | 僅引用結果;不執行路線 |
| **路線執行率** | 完成的多跳執行分為有效的執行嘗試 | 僅適用於實施執行系統;每次報告和原子性規則 |
| **擔保人回收** | 收到的資格回報,分為已支付的受保索賠 | 確定擔保人,索賠政策,時間表,成本,爭端和抵免 |
| **擬議的網路收入** | 收到的擬議網路拉克加上收取的單獨路由/服務費 | 排除池所保留的毛額費用,避免兩次計數拉克 |
| **管理及時性** | 發現,決定,暫停,修復和關閉事件的時間 | 定義時鐘,負責機構,緊急權力,上訴和失蹤事件 |

區塊鏈活動本身並不能確定身份,發行方的表現,滿意度,社群健康,因果關係或影響.
