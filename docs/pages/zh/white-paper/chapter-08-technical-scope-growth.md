## **8. 技术范围和增长**

本章把当前生产路径服务与可选或拟议扩展区分开来。这里所述当前功能属于公开 CLC App/Core 部署；它不是 Protocol v1.1.0 合约或其他部署自动具备的功能。

目前的公开部署包括:

- 基于图的发现，用于查找可通过兼容资金池获得的代金券；
- 为选定同链路径生成权威固定区块报价；
- 逐跳计算资金池费用、协议费用、最低输出和截止时间；
- 完整批次模拟、参与者签名和 Calibur 中继执行；
- 一笔同链交易，任何调用失败都会回滚所有路径调用；以及
- 分组收据和逐跳结算事件对账。

可能的增长领域包括:

- 在原子结算不可的情况下,用于跨域执行的时间锁定托管或HTLC适配器;
- 其他注册表或政策配置，以及跨配置路径；
- 选择参与库存再平衡和批量结算;
- 小型或个人资金池的接口和政策工具;
- 可审核的凭证,汇总,汇率方法,限额,控制者和费用登记册表;
- 具体部署的支付提供商连接器,现金流和资格控制;
- 复合资产与外部流动性场所的连接,用于重新平衡和支付流动性的;以及
- 通过的覆盖范围,运营成本或流动性授权的政策资金转换.

外汇市场价格不会决定发行者根据券条款所欠的债务.一个集团可以对可置资产使用保护的外部参考,但其公布的汇率方法,限制,费用和库存将控制其报价.

### **8.1 当前路径服务和更广泛的规范**

**发现。** CLC Core 根据已配置目录、注册表关系、资金池参数、费用、限制、余额和链上事件维护经过对账的图。它估算会话钱包可到达的资产，并标记过时数据。公开配置最多搜索三跳路径。发现结果不是可执行承诺。

对于选定路径，CLC Core 在同一个固定区块读取参与资金池，并重现受支持的 `SwapPool` 计算。它逐项列出资金池费用和协议费用，为每一跳设置最低输出和截止时间，准备钱包调用，并模拟完整批次。不受支持的代币、报价器、钱包或资金池条件会被拒绝。

**当前执行。** 参与者签署一个 Calibur 批次，其中包含每一跳的 allowance 重置、allowance 授予和带边界的提取。中继器提交一笔启用 `revertOnFailure` 的同链交易。这为当前路径提供交易级全有或全无行为，但不等于跨链原子性、HTLC 或托管路径、自动再平衡或净额结算。

**收据和运营。** 应用用一个跟踪 ID 汇总路径，并记录交易状态、跳转顺序、资金池、代币对、报价和结算金额、资金池费用、协议费用和中间余量。服务监测图的新鲜度、路径数量和报价结果、模拟失败、中继时长、对账和纠正，以及未解决或未知的索引成员。运营遥测不能证明发行方履约。

客户端可以支持多个注册表根或政策配置。它应向参与者说明报价使用的配置、交易对手、适配器、限制和责任服务运营方。跨配置路径必须满足每一跳的所有适用条件。

可问责的运营方可以排除不安全的依赖项或交易对手，并应用路径级上限、新鲜度要求和健康标准。这些信号可以辅助决策，但不能保证履约或防止损失。

**费用和限制。** 当前报价列出每一跳的资金池费用和任何额外协议费用。公开应用目前不会另收路径服务费。任何未来服务费都会单独披露。执行会拒绝过期报价或违反边界的交易。

**跨域原子性和恢复。** 如果未来路径无法使用当前同链原子批次，而是使用 HTLC 或托管，服务应披露超时、中止路径、责任控制方、事件流程和剩余风险。

**拟议的批量净额结算和再平衡。** 选择加入的服务可以收集再平衡意图，并搜索兼容的循环或链。它将：

1. 发布机器可读的收据，标明执行周期、资产、金额、估值时间戳和费用；
2. 执行每期采用的上限和对手政策;
3. 拒绝任何违反参与池的授权,限制或可用库存的活动;
4. 保存确定性输入和收件以进行审查和纠纷处理.

**SDK 和界面要求。** 可复用的路径集成应提供确定性的报价到收据映射、逐跳不变量检查、易于理解的故障代码和便于审计的日志。当前生产 App/Core 实现为其自身配置提供这些功能。Protocol v1.1.0 的 Solidity `SwapRouter` 仍仅用于报价，不执行路径。

#### **8.1.1 最低联盟兼容性规范**

寻求跨配置路由的Pool生态系统将为:

1. **数据库的根源:** 资产,汇总,汇率方法,限制和费用政策的标识符或确定性解决它们的一个根.
2. **收据:** 每次跳跃的个人资料,进出资产,金额,报价来源和时间标签,限量快照,费用,库存结果和执行结果.
3. **运行信号:** 关于库存,限量利用,事件以及任何单独证明的履行或资助保护的新鲜信息.
4. **政策限制:** 允许或拒绝的对方,资产类别,适配器以及任何保证金要求.
5. **失败代码:** 拒绝,过期,限制,库存,政策,依赖性或事件故障的决定性解释.

一个配置文件可以添加覆盖,合规性,仲裁或其他服务,而不会使它们成为基本CPP兼容性的要求.每个可选的服务都会确定其负责人,权威,范围和条款.

### **8.2 许可,验证和退出**

Protocol v1.1.0 合同是EVM-协议存储库中的合同 `src` 文件目录在AGPL-3.0除了已确定的未修改的第三方组件,这些组件保留了自己的条款. 发表的源头,ABI和部署说明支持独立审查,但本身并不能证明审计,安全部署或法律合规性.

每个部署将单独披露其代码版本,构建来源,地址,控制器和升级权力,审计状态,注册表镜像以及任何时间锁定或暂停保护.

拟议的 **叉子套件** 可能包括:

1. 确定性部署脚本;
2. 登记快照和出口工具;
3. 一个为重定路线服务,SDK和接口的记录过程到一个新的注册表根;
4. 一个资金池管理者安全离开共享注册表的检查清单;以及
5. 一份未发行券的迁移检查清单,包括发行人通知,提交和履行截止日期,继续访问记录以及补救措施.

当社区,合作社,公共机构,联邦,多业务或服务运营商需要不同的治理时,兼容的叉子可以提高弹性.实际连续性仍然取决于合同所有权,钥匙,依赖性,接口,基础设施,法律义务和第三方服务.
