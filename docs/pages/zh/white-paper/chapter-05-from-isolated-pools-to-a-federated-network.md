## **5. 从孤立的资金池到联合网络**

当前 Protocol v1.1.0 支持通过一个 `SwapPool` 直接执行，并提供仅用于报价的 Solidity `SwapRouter`。生产环境中的 CLC App 和 CLC Core 通过准备一个已签署的 Calibur 钱包批次，协调由参与者发起、经过最多三个资金池的同链路径。合约本身不会执行多跳路径；当前 App/Core 流程也不提供跨链 HTLC、托管路径、自动资金池再平衡、批量净额结算或跨网络清算。

本章说明当前的参与者路径，并把它与需要新增资金池权限的拟议协调方式区分开来。在两种情况下，独立资金池都保留自己的准入、估值、限制、费用、库存、授权和治理规则。

### **5.1 分别衡量交换与履约**

路径服务可以改善库存获取，但不会合并代金券和兑换生命周期。衡量时应把以下事件分开：

1. 路径获得报价；
2. 一次或多次资金池兑换在链上执行并结算；
3. 持有人向发行方出示代金券单位；
4. 发行方履行承诺；以及
5. 已履约单位被核销。

报价或执行路径的增加并不能证明履约增加。报告应说明附录 C 要求的群组、期间、资产、估值方法和时间戳、排除项、纠正政策及链下证据。

**路径示例：** 一所学校持有玉米代金券，但需要运输代金券。CLC Core 可以识别兼容的资金池库存，在同一个固定区块为选定路径生成报价，并为学校钱包准备带边界的调用。只有每一跳都满足报价边界、限制、费用、库存、受支持行为和政策，执行才会成功。最终兑换不能证明任何发行方后来履行了代金券承诺。

### **5.2 当前参与者路由和拟议的再平衡**

两类活动需要不同的权限。

**当前由参与者发起的执行。** CLC Core 根据输入和输出代金券及金额，从参与者符合条件的持仓中估算路径。对于选定路径，它在同一个固定区块读取资金池，生成权威报价，模拟完整批次，并为每一跳准备三次调用：重置 allowance、授予 allowance，以及带边界的 `SwapPool.withdraw`。参与者签署后，中继器提交一笔启用 `revertOnFailure` 的同链 Calibur 交易。任何调用失败，所有路径调用都会回滚。应用把交易和逐跳结算汇总为一张收据。

每一跳都保留各自的责任资金池、报价输入、授权、费用、限制、库存和结算事件。当前应用不会另收路径服务费。当前流程支持与应用兼容的 EOA/Calibur 钱包，不支持 Safe 或其他合约钱包。

**选择加入的资金池再平衡。** 资金池管理者可以公布库存目标、允许的交易对手、资产类别、报价偏差边界和每期限制。可问责的服务可以搜索兼容的循环或链条，并且只执行已授权意图。

再平衡必须由资金池选择加入。资金池可以允许普通参与者使用路径，而不授权服务移动库存进行再平衡。未来授权可以仅允许特定资产、交易对手和金额。每次执行的跳转都应产生收据，任何服务费应与资金池费用和协议费用分开披露。

跨链 HTLC 或托管执行也与当前同链原子批次不同。它需要已采纳的超时、中止、控制方、恢复和剩余风险规则。

#### **5.2.1 联邦和互操作性**

独立部署可以运行自己的注册表、界面、路径服务和政策配置，同时选择兼容的数据和收据标准。当前公开 App 使用其已配置的注册表和服务配置。跨配置执行仍取决于部署。

兼容配置应：

- 确定其注册表根、服务运营方、控制者和适用条款；
- 披露允许和拒绝的对方,资产,适配器和路线;
- 适用于每个参与池的授权,限制,费用和库存约束;
- 保存每次报价到收件证据;以及
- 允许其他功能的库离开或选择另一个注册表,而不删除余额或发行人义务.

兼容性可以增加可用兑换路径，并减少对单一注册表或运营方的依赖。它不会让网络、CLC App、GEF 或其他资金池对某个发行方的履约负责。

### **5.3 拟议的网络费用分成与服务费模型**

当前 Protocol v1.1.0 对直接的组交换征收了组费,并在配置时还征收了一个额外的协议费.

生产环境中的路径兑换会在每一跳独立应用这些当前费用，并在报价和收据中逐项列出。它目前不会另收路径服务费。

未来的项目可以单独获得:

1. 一个 **网络拉克** 定义为参与池收取的池费中的所述份额;以及
2. 一个 **路由费或服务费** 为了确定未来的服务.

拟议的网络拉克不是已经计算组费后,对全部交换金额的附加百分比.对于组 `p`:

τ_p = f_p · r_p

在哪里 `f_p` 是池费率和 `r_p` 是该组费所分配给网络计划的拟议份额.

在测量期间:

- **总池费** 是每个集团实际收取的集团费用的总额;
- **网络冲击收据** 是这些收取的费用所声明的份额;
- **服务费收据** 是单独收取路由费或服务费;以及
- **项目费收据** 同等的网速收益加上服务费收益.

任何类别都不会被计数两次.除非通过单独的政策,否则将实际的协议费收益合法转向未来计划,目前的协议费不包括.

对于总体近似,让:

- `Q_swap` 是对定义的队列和期内执行的组交换值;以及
- `τ` 是拟议的网络拉克的有效率,以及对执行的交换价值进行了单独确定的服务费.

然后:

F ≈ τ · Q_swap

每个输入都需要一个明确的队列,周期,单位,估值时间表,排斥和纠正政策.

#### **5.3.1 符合现金条件的收入与实物收入**

任何交换或转换都需要授权,可用库存,披露场所,限制和实际执行.

让 `χ` 是政策限制,转换失败和滑坡后现金资格的收费收益的实现份额.可使用现金的收益是:

F_cash ≈ χ · F

预算和破产平衡分析将使用实现的 `F_cash`,而不是总上市费用或物质库存的表值.未来的计划将单独报告集团费用,网络收益,服务费,资产组成,转换结果和可使用现金收益.

### **5.4 拟议的流动性计划**

未来,单独记录的流动性计划可能将资产分配给指定池或路由服务.当前的 `SwapPool` 合同不会打印池股,也不会自动创建偿还,提款,奖励,治理或利权.

任何程序都会发布:

- 负责实体和参与的资金池管理者;
- 贡献的资产以及转让是否可偿还,可撤销,捐赠或授予;
- 监护和技术控制安排;
- 允许使用,限制,锁定,退出门和损失分配;
- 费用或激励金的资格,以及该金额是否可能为零;
- 报告,冲突,投诉和补救措施;以及
- 转移,终止和处理剩余资产和义务.

实质性风险包括难以交换或履行的库存,现金资格较低,发行方未能执行,合同或供应商失败,治理变化和退出限制.限制,储备,收据和仪表板可能会减少或揭示一些风险;它们不会消除损失.

对于后期分析指标,让:

- `ϕ` 是根据该计划通过的条款分配的项目费收益的实现部分;以及
- `K` 是该计划所涵盖的资产在一个指定的方法下衡量的价值.

然后:

FeeFlow_LP ≈ (ϕ · F) / K = (ϕ · τ · Q_swap) / K

该指标描述了每项测量项目资产的履约费用流动.它不是APY,预测,股息或保证收益.报告将保持交换量,赎回表现,发行人履行,清算,持有时间,损失,提款和费用收据分开.
