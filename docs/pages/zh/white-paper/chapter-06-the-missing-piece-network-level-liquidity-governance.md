# 6. 拟议的网络级流动性和治理

历史性 Sarafu Network 的经验激励了研究两个更广泛的设计问题:

1. 独立治理的资金池如何协调流动性和路径服务；以及
2. 如何随着参与的增长,共享服务可以继续承担责任.

一项拟议的 CLC 设计引入**拟议的 CLC 网络资金池**，作为网络级清算和预算协调安排，并引入**拟议的 CLC 治理代币**。当前 App 或 Protocol v1.1.0 都不包含这两项。其他部署可以采用合作社、公共机构、联合会、多签、服务运营方或其他可问责结构，而不采纳任何一项提案。

## **6.1 下行风险控制与选择权**

目前的 Protocol v1.1.0 可以应用Pool代币平衡上限和库存检查. 这些控制限制了选定的合同行动;它们不会防止发行方不履行,损失价值,关键损失,合同失败或其他任何损失.

未来的部署可能会增加断路,时间限制,储备,保证或保险.任何保护都需要确定一个负责人,涵盖事件,资金,限额,排斥,持续时间,证据,索赔程序和适用的条款.

拟议的治理应保持注册和服务权限的狭窄性和可审查性.普通行动可以使用通知,延迟,理由发布,上诉和纠正过程.紧急行动应该产生事件记录,并根据采用的政策到期或接受审查.

生产环境中的 CLC App 和 CLC Core 现在通过已配置的公开服务，为参与者授权的路径提供兼容路径发现和同链多跳执行。报价会应用逐跳限制、费用、库存、边界和模拟；已签署的钱包批次若有任何调用失败，就会整体回滚。

这项服务不授权自动再平衡，也不授予网络层面对库存的控制权。再平衡、批量净额结算、跨域 HTLC 或托管执行，以及共享流动性治理，都需要额外权限、软件、限制、故障处理和已采纳规则。更多报价或已执行兑换本身不能证明代金券履约或社会影响。
