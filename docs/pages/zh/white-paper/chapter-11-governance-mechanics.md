## **11. 治理机制**

本章提出了治理模板.它并不代表当前的 CLC App 使用治理代币投票,时间锁定,共享保险,索赔流程或下面描述的所有控制.每个部署都需要确定其实际决策者,当局,合同,过程和政策.

- **宪法价值观:** 人们的关怀,环境的关心,公平性,互惠,非主导性和弹性.
- **提案类型:** 费用,限额和指数变化;流动性授权;集团上市和撤销;可选的覆盖决策;参数保护.
- **负责的过程:** 认可可能来自管理员,合作社,公共机构,联合会,多合伙人,连锁投票或其他公开和负责任的结构.
- **批准门:** 按行动类进行参数,对价值指数变化,紧急权力和其他关键行动的门更高.
- **代表:** 提供公共任务,冲突披露和召回的可选授权.
- **电路打断器:** 紧急暂停,有明确的标准,授权运营商,恢复条件和必要的死后检查.
- **透明度:** 已公布的变化和流动,附有对交换结算,发行人履行,储备,使用限额,路由和担保人的单独证据.

**登记管理.** 一个CPP-兼容的部署可以维护券,代币和资金池的发现登记.授权控制器可以通过部署的披露管理过程添加,更新,暂停或删除注册表输入. 注册表的删除影响了该登录的发现和路由;它不会自行删除代币,改变持有者的余额,履行发行人的义务,或禁用其他功能合同.

发布的登记规则应使状态有条件,并可能将重复不履行,欺诈或虚假陈述,不安全的合同行为或持续违反公布原则作为暂停或删除的理由.在可行的情况下,该过程应该提供通知,补救机会和上诉途径.紧急删除需要公开事件报告和自动审查或日落.

**禁止列表.** 在本模板下,注册表不允许:

1. 直接资助或激励超越达成的边界,暴力或武器化,强制采集或系统滥用的生态破坏工具;或
2. 没有明确的表达和履行条款,责任和补救途径.

禁止清单只能通过采用已通过的关键行动门和时间限制进行编辑,公开审计和可变化,如下说明:Q3 + T3在附件D中.

### **11.1 汇率和限制治理**

**时间限制的变化.** 根据本模板的部署,只有在公开时间锁定后才会改变汇率方法和单独实施限制参数.紧急路径将使用单独披露的授权过程,并包括自动日落或审查.

**批准门.** 该模板提出了价值指数基因变化和全球限制级别变化的更高批准门,对于特定组的第三方变化的中期门以及常规费用变化的标准门.

**发布的数据.** 一个参与的部署将为每个组发布连锁指数变量,预言源或中位数,更新序列,限制窗户和封顶以及故障模式或安全常态.

**紧急暂停的标准.** 参与部署将预示诸如神器中断,高限度使用与履行故障或不变性故障等条件,以及恢复检查和事故后审查要求.

**一个池和券的公共索引料示例**

- **标志:** 例如,`Maize_50kg@IssuerY`.
- **参考单位:** 指数单位 (IUX).
- **发布值:** 30.000 IUX.
- **来源:** 确定来源的中位数,例如当地市场调查,部署公告和部署基线.
- **更新时间:** 每天18:00 EAT,有24小时时间锁定.
- **失效模式:** 在最后一个有效值上结,应用披露的限制政策,并在72小时停机后暂停.
- **理由:** 已公布的备忘录和以前更新的变化记录.
- **签署者:** 披露的多标签地址和批准门.

### **11.2 拟议的保险基金操作手册**

**只有可选的设计.** 本行本仅适用于已明确采用和资助保险基金的部署,并发布了涵盖事件,有资格的索赔者,负责人,资产,限制,排除,证据要求,程序和管理条款.CLC App 没有 GEF 仅因为该设计出现在白书中,就能提供覆盖.

**可能是触发器.** 通过的政策可能涵盖定义发行人不履行,库存缺陷或桥梁或保证金损失.

**评价.** 负责机构将调整交易收据,库存余额,担保人债券,赎回提交记录,发行人的响应和其他必要证据,然后发布与隐私和法律一致的事件记录.

**显著的损失布.** 如果每个层都存在且合法适用,则保险可以使用: (1) 负责任发行人债券或担保人股份 → (2) 储备水平 → (3) 拟议的网络保险基金 → (4) 暂时降低到可选的覆盖索赔,只有当现有条款和适用的法律明确授权它 → (5) 对被证明的欺诈或滥用行为进行合法回收.

覆盖率调整不会减少发行人的基本券承诺或改变连锁余额,除非有效的现有条款和适用的法律明确允许该结果并获得所有要求持有人同意.

**限制和排除.** 发布的覆盖范围将定义上限,符合条件的呈现,证据,索赔窗口,排除路线或事件,地理限制以及处理耗尽储备.

**显著的恢复时间表.** 如果通过并公布:

1. 索赔首先来自负责发行者或担保人债券,然后从适用的库存储备,然后是拟议的网络保险基金;
2. 任何降低到可选的覆盖索赔将仅限于现有覆盖条款和适用法律授权,直到公布的事件上限;
3. 恢复计划可以在指定期内运用已确认的回收价值份额,之后任何剩余的覆盖赤字将成为公开死后的记录损失;
4. 每个决定都会提供一个收据,其中包含事件ID,受影响的索赔和凭证,决定,恢复计划和上诉窗口.

### **11.3 担保框架**

根据本节,分别区分了发行人责任,可选的池保护和第三方保证.CLC App, CPP, GEF 任何更广泛的网络都会自动保证券.

**基本发行人责任**

- 发行者承诺根据其公布的条款提供所述商品,服务或合法的现金等价.
- 发行方将公布谁可以提交凭证,什么是满足意味着,在哪里和何时可用,需要哪些证据,以及适用的补救措施.
- 如果发行人未能履行,发行者是首要负责人. 池或网络保护只适用于单独采用,资助和披露时.

**可选的池保护**

一个资金池管理者可以选择将一个严格定义的保护添加到被录取的凭证中.它不是自动的,并且需要在库的元数据和适用条款中识别负责人,资金,有资格的活动,限额,窗户,证据,排斥和补救措施.

说明性保护类型包括:

1. **储备资产覆盖范围:** 经验证的发行人未履行后,负责集团实体将以指定储备资产支付一笔确定的金额,但须按其公布的上限和可用资助储备.
2. **转换窗口:** 资格化事件后,集团提供一个限时的交换途径进入此前或其他批准的资产,受限制和库存约束.这是基于库存的流动性保护,而不是承诺每个交换都是可逆的.
3. **替代性履约:** 负责人在公布的数量或价值上限范围内安排批准的替代供应商.
4. **汇率带保护:** 对于选定的券类别,一组只提供在其现有条款中所述的覆盖性调整或交换回收补救措施.这不会减少发行者的基本券义务.

**可能的资金来源**

- **发行人债券:** 发行人投放或在公开储备中持有的抵押金,并在经过验证的覆盖事件后可用.
- **池储备:** 由负责池组实体控制的资产,并分配给其宣传的保护.
- **第三方担保人债券:** 已确定的外部担保人对所述发行方,代金券类别或事件的抵押金.

担保人参与将遵循公布的资格标准,债券规模,集中限额,决策权和法律执法规则.

**索赔程序**

通过的一项政策将定义可审核的触发因素,例如在有效赎回提交后错过的履行期限,经过验证的发行人破产性,已覆盖的桥梁或保证券失败或正式宣布的事件情况.

- 参与者如何开放索赔,并提供所需的提交和履行证据;
- 验证券条款,发行人回应和技术记录;
- 裁决和上诉窗口;
- 授权的支付路径,资产,上限和收据.

从发行方,仲裁或法律执法获得的收益将根据公布的政策重新填补适用的债券或储备,然后用于拟议的CLC网络池交换访问.

**要求披露信息**

对于每个覆盖的池和券类,负责人将公布:

- 担保人是否缺席,是自愿的或有义务的;
- 债券或储备规模和度上限;
- 保护类型,资产,盖顶,窗户和排除;
- 提交,履行,索赔和上诉的最后期限;以及
- 一个明确的声明,说明谁能保证什么以及什么不能保证.

**监护原则.** 资金池管理者负责法律或治理结构为他们所宣传的保护负责.CPP-兼容的部署可能提供标准,注册表或可选共享政策,但没有CLC没有 GEF 无需提供任何资金,

### **11.4 防止治理俘获的保障措施**

根据本模板,以下是需要采用的最高审批级别和长时间限制的关键行动:

1. 改变拟议的费用布,包括其覆盖范围和核心运营优先事项;
2. 修改法典登记库的根;
3. 变化覆盖范围,索赔上限或决策权威;
4. 扩大紧急暂停权限;或
5. 削弱在本文中所述的 Pool叉性,透明度或集团主权承诺.

### **11.5 分叉与退出程序**

如果治理被捕获或价值大幅漂移,社区,资金池管理者和运营商可以通过断网络治理层来寻求退出.底层池和凭证的连续性将取决于部署的合同,钥匙,接口,基础设施,第三方服务以及适用的义务.

退出过程可能:

1. **发布快照:** 输出选定的注册表,凭证,价值,限制和费用政策,然后发布签署的快照哈希.
2. **重新部署治理服务:** 在新的负责任结构下部署新的登记根,路线服务和任何采用的费用或覆盖模块.
3. **重新注册:** 允许资金池管理者通过在新的根下注册自己的池地址进行选择,而不需要持有者迁移其他功能代金券.
4. **重新调用客户:** 在 SDK 和接口中添加新的根作为可选择的网络配置文件,并通过披露的治理过程进行任何默认更改.
5. **管理一个桥梁时期:** 保持安全的兼容路线,并拒绝违反新配置规则的路线.

设计的目标是,离开正规注册表不会禁用其他功能的本地池.实际连续性仍然取决于部署;联邦是一个选择发现和协调层.
