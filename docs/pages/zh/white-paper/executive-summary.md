# 执行摘要

**Commitment Pooling Protocol（CPP，承诺汇聚协议）** 说明独立治理的承诺资金池如何筛选可兑付承诺、公布汇率方法和限制、持有库存，并支持可问责的交换。发行方仍对自己的代金券承诺负责。资金池管理者仍对资金池规则及明确承担的保证负责。CLC App 和 GEF 都不是普遍担保人。

Protocol v1.1.0 提供当前直接兑换的基础组件：`GiftableToken`、`SwapPool`、可选注册表和估值模块、资金池代币余额上限、资金池费用、额外协议费，以及仅用于报价的 Solidity `SwapRouter`。生产环境中的 CLC App 和 CLC Core 目前可以发现最多经过三个资金池的同链路径，生成固定区块报价，模拟和准备已签署的原子钱包批次，进行中继，并汇总其结算记录。合约仍不会记录现实世界履约、自动创建流动性提供者份额、执行跨链路由或批次净额结算，也不会提供普遍的储备、保证或保险。

历史上的 **Sarafu Network** 曾在社区货币、储蓄小组、互助系统和生产承诺中使用承诺汇聚概念。该服务后来转向 CLC App。这并不表示每个历史账户、钱包、代币、代金券、资金池、余额、报告、参与者或义务都已迁移。

更广泛的 CLC 设计把当前路由与以下提案结合，探索兼容网络如何能够：

1. 将可问责的路径服务扩展至更多注册表或政策配置及领域；
2. 协调可问责的网络服务，而不取代当地责任；
3. 支持单独出资的流动性授权计划、保证、储备或保险政策；
4. 将资金池兑换与代金券出示、履约和核销分别衡量；以及
5. 利用拟议网络费用分成和另行采纳的服务费，为共享服务提供资金。

提案包括 **拟议的 CLC 治理代币** 和 **拟议的 CLC 网络资金池**。二者都不是当前 App 或 Protocol v1.1.0 的组成部分。

在拟议模型下，流动性和治理参与者只能通过另行采纳的计划参与。这些计划须公布资格、风险、控制、转让权利、收回条件和费用规则。普通资金池存入不会自动产生份额、偿还、提取、奖励或治理权。

共同目标是：

> 增加可问责的交换，促进现实世界承诺的履行，同时保持关爱、公平、当地责任和韧性。

防止控制权被攫取和可信退出，仍是核心设计目标。拟议控制包括延时治理、多重批准门槛、透明授权、利益冲突规则、事件复核，以及有记录的分叉和迁移流程。这些措施可以降低部分治理风险，但不能消除损失或保证结果。
