# 执行摘要

**承诺汇集协议（CPP）**描述了独立管理的承诺资金池如何管理可兑换的承诺、公布汇率方法和限制、持有库存并实现负责任的交换。发行者仍然对其凭单承诺负责。资金池管理者继续对汇集规则及其明确承担的任何担保承担责任。CLC App和GEF都不是普遍担保人。

Protocol v1.1.0提供了当前的直接互换构建模块：`GiftableToken`、`SwapPool`、可选登记册和估值模块、池令牌余额上限、池费用、附加协议费以及仅报价的Solidity`SwapRouter`。生产CLC App和CLC核心现在可以通过多达三个池发现同链路径，生成固定区块报价，模拟并准备签名原子钱包批次，将其转发，并将其结算记录分组。合约仍然没有记录实际履行情况，创建自动流动性供应商股份，执行跨链路由或批量净化，或者提供通用储备、担保或保险。

历史上的**Sarafu Network**使用跨社区货币、储蓄小组、互助系统和生产承诺的承诺汇集概念，其服务后来过渡到CLC App。 这并不是说每个历史账户、钱包、代币、凭单、池、余额、报告、参与者或义务都迁移了。

更广泛的CLC设计将当前路由与关于兼容网络如何能够:

1. 将负责任的路由服务扩展到其他注册表或策略配置文件和域;
2. 协调负责任的网络服务，但不压倒地方责任；
3. 支持单独供资的流动性授权、担保、准备金或保险政策；
4. 将池互换与凭单出示、履行和结算分开计量；并且分别计量池互兑和凭单交割。
5. 使用拟议的网络收费和单独通过的服务费来为共享服务提供资金。

该提案包括**拟议的CLC治理令牌**和**提议的 CLC 网络池** 。 两者都不是当前应用程序或Protocol v1.1.0的一部分。

根据拟议的模式，流动性和治理参与者只能通过单独通过的计划行事，该计划公布资格、风险、控制、转让权利、回收条件和费用规则。普通池存款不会产生自动分享、偿还、提取、奖励或治理权。

共同目标是：

> 增加负责任的交流和履行现实世界承诺，同时保持关怀、公平、地方责任和复原力。

防捕获和可信退出仍然是核心设计目标。 拟议的控制措施包括时间延迟治理、多个批准阈值、透明授权、冲突规则、事件审查以及有记录的分叉迁移流程。 这些控制将减少选定的治理风险，但无法消除损失或保证结果。
