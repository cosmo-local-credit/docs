# 代金券实际示例

本示例跟随一张代金券经历发行、资金池交换、兑付出示、履约和核销的完整过程。它用于说明各方角色，并不承诺任何特定代金券、资金池、路径或结果一定可用。

相关定义见 [概念和术语](/zh/introduction/concepts)。

## 1. 发行方公布一项承诺

假设一家社区厨房创建了数字餐券。发行前，厨房会公布持有人作出知情决定所需的信息：

- 厨房的身份和联系方式；
- 一张代金券代表的餐食或其他商品或服务项目；
- 供应量、单位、标示价值以及厨房的履约能力；
- 可以出示代金券的地点和时间；
- 到期日、预约流程、费用、税费或转让限制；以及
- 兑付出示、履约、投诉、退款、替代方案和其他补救措施如何运作。

厨房是发行方。它必须确保这些信息准确，不得超出合理能力发行代金券，并按照持有人取得代金券时适用的条款履行承诺。创建代币或发布商品或服务项目，不能证明厨房具备相应能力，也不会使 GEF 成为发行方。

## 2. 资金池管理者准入代金券

一个关注粮食安全的承诺资金池会审查厨房、代金券条款和资金池自身目的。如果代金券获准进入，资金池管理者会公布适用规则，包括：

- 谁对资金池负责；
- 当前 `SwapPool` 所有者、代理管理员和重要依赖项的控制者；
- 接受哪些资产；
- 汇率或报价方法；
- 代币余额上限，即应用中所称的 **“信用额度”**；
- 资金池费用和协议费；
- 库存以及提取流动性的权限；以及
- 任何另行提供资金的保证、储备或支持安排。

准入只表示资金池配置的规则允许使用该代金券。它不能证明发行方具有履约能力，不会确定现金价值，也不会自动形成保险。

## 3. 参与者提供库存

支持者按照适用的已公布条款，把餐券或另一项受支持资产转入 `SwapPool`。这笔存入会增加可用库存。

该转移不会自动产生资金池份额、偿还请求权、提取权、奖励或治理权。任何此类权利都必须来自另行披露的安排。

## 4. 持有人进行资金池交换

持有人通过资金池，把一种受支持资产换成餐券。界面显示的报价是已配置报价器生成的交易参数，并不能证明餐券的现金价值或厨房的履约情况。

直接资金池交换通过转移输入资产、输出资产、资金池费用和任何额外协议费在链上结算。它不会自动构成贷款、发行方兑付或现实世界的履约。

## 5. 持有人出示代金券

在当前应用中，选择 **“兑付”** 会打开普通发送流程，并预先填入代币所有者的地址。把代金券发送回去可以作为向发行方出示兑付的证据；这本身不能证明厨房已经提供餐食。

厨房核实出示情况，并按照已公布的条款提供所承诺的餐食。

## 6. 发行方记录履约与核销

提供餐食后，发行方会记录已经履约的代金券单位，防止它们被重复出示。根据已公布的流程，这可能包括接收、销毁、取消或以其他方式停用已退回的代金券。

如果厨房没有履行承诺，持有人应使用发行方公布的投诉或补救流程，并行使适用法律提供的权利。应用展示了代金券，或资金池支持了交换，并不会因此使 GEF 或资金池管理者成为兑付方。

应用中的 **“停用代金券”** 是另一项操作：它会隐藏目录上架，但余额和历史记录仍然存在，管理员也可以恢复上架。它不等于履约、核销、销毁或取消。

## 职责一览

- **发行方：** 说明并履行代金券承诺，记录核销。
- **资金池管理者：** 公布并管理资金池的规则、汇率、费用、限制、控制措施以及明确承担的任何保证。
- **持有人：** 审查发行方、代金券条款、资金池规则、报价、钱包授权和适用法律。
- **技术控制者：** 仅行使分配给他们的合约、依赖项、升级、目录或费用权限。
- **GEF：** 按照 [服务条款](/zh/governance/terms) 运营 CLC App 和配套基础设施；它不会自动承担上述其他角色。

## 未来的信贷安排

未来，某个资金池或其他责任方可以另行把一项交易作为可偿还预付款、有担保交易或其他信贷产品提供。此类产品需要另行提供补充条款和交易条款，明确当事方、金额、到期日、费用或利息、抵押品处理、转让、违约、补救措施和核销证据。

普通发送、资金池存入、资金池交换、兑付出示、履约或核销，本身不会产生这些义务。
