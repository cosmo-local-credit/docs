# 代金券交换示例

这些示例说明代金券、需求、资金池、交换、履行和解除之间如何相互关联但彼此不同。它们用于说明相关角色，并不承诺某张代金券、某个资金池、某条路线或某种结果一定可用。

相关定义请参阅[概念与词汇](/zh/introduction/concepts)。

## 简单示例：一个资金池，三名参与者

一位农民提供食品篮，需要牙科服务。一位修理工提供车辆维修，需要食品。一位牙医提供牙科服务，需要车辆维修。

每名参与者都创建一张条款清楚的代金券，并发布一个商品或服务项目：

- 农民的代金券可以用于食品篮；
- 修理工的代金券可以用于维修服务；以及
- 牙医的代金券可以用于牙科服务。

牙医创建一个名为 **Health Market** 的承诺资金池，公布规则，准入三种代金券，并存入一些牙科服务代金券。资金池配置的代币余额上限决定它最多可以持有多少农民和修理工的代金券。App 中的这些 **“信用额度”** 是资金池容量控制，不是个人贷款。

农民看到牙医对本地食品的需求，查看牙医的代金券和资金池条款，然后用食品篮代金券换取牙科服务代金券。农民随后预约、出示牙科服务代金券、接受承诺的治疗，牙医再记录解除。

修理工用维修服务代金券换取资金池中已有的食品篮代金券，并用它们获得食品配送。牙医可以用牙科服务代金券换取修理工的维修代金券，再用它们维修车辆。

每次资金池交换都会结算代金券余额。每个发行方仍分别负责提供承诺的食品、维修或牙科服务。资金池使多方交换成为可能，不要求每一对参与者都在同一时间恰好需要对方提供的东西。

## 进阶示例：路由交换

本例说明一张代金券如何从商品或服务项目和需求出发，通过两个独立治理的资金池完成交换。

### 1. 发行方公布一项承诺

假设一家社区厨房创建数字餐食代金券。发行前，厨房公布持有人作出知情决定所需的信息：

- 厨房的身份和联系方式；
- 每张代金券所代表的餐食或其他商品或服务项目；
- 供应量、单位、标示价值以及厨房的履行能力；
- 可以在何处、什么时间出示；
- 有效期、预约流程、费用、税费或转让限制；以及
- 出示、履行、投诉、退款、替代和其他补救如何处理。

厨房是发行方，必须保持信息准确，避免发行超过合理履行能力的数量，并按照持有人取得代金券时适用的条款履行承诺。创建代币或发布商品或服务项目，不能证明厨房具备履行能力，也不会使 GEF 成为发行方。

厨房还发布一个描述可用餐食的 **商品或服务项目（Offering）**。代金券和该项目相关但不同：代金券是可兑换的承诺，而商品或服务项目帮助人们发现相关商品或服务。

### 2. 参与者发布需求

附近一所学校持有交通代金券，需要为一次活动准备餐食。学校发布一项 **需求（Want）**，说明餐食、数量、地点、时间和联系方法。

需求用于表达需要。它不会自动接受厨房的代金券、预留餐食、创建合同、授权交换或承诺学校一定继续交易。学校仍需审查厨房、代金券条款、可用路线、报价和适用条件。

### 3. 独立的资金池管理者筛选路线

两个独立治理的资金池连接这些资产：

1. 一个交通资金池准入学校的交通代金券和一种玉米代金券；以及
2. 一个食品保障资金池准入同一张玉米代金券和厨房的餐食代金券。

每个资金池管理者分别审查资产并公布本资金池的规则，包括：

- 谁对资金池负责；
- 当前 `SwapPool` 所有者、代理管理员和重要依赖项控制者；
- 准入的代金券和其他受支持资产；
- 汇率或报价方法；
- App 中称为 **“信用额度”** 的代币余额上限；
- 资金池费用和协议费用；
- 库存和提取流动性的权限；以及
- 任何单独出资的担保、储备或支持安排。

准入表示资金池配置的规则允许该代金券，但不能证明发行方具备履行能力、建立现金价值、形成保险，也不会把两个资金池变成同一个治理实体。

### 4. 参与者提供库存

交通资金池持有可用交通代金券交换的玉米代金券。食品保障资金池持有可用玉米代金券交换的餐食代金券。不同参与者可能按照不同的公布安排提供这些库存。

存款会增加可用的资金池库存，但不会自动产生资金池份额、还款请求权、提款权、奖励或治理权限。任何此类权利都必须来自另行披露的安排。

### 5. App 发现路线并提供报价

学校的钱包打开 **可存入（Credit）** 视图并选择餐食代金券。CLC Core 估算一条可能的路径：

`transport voucher → mobility Pool → maize voucher → food-security Pool → meal voucher`（即：交通代金券 → 交通资金池 → 玉米代金券 → 食品保障资金池 → 餐食代金券）

这个发现结果还不是交换一定成功的承诺。每一跳都取决于当前准入、资金池代币余额上限、可用库存、报价和费用配置、受支持的代币行为以及服务数据是否及时。

学校选择想要 **获取（Get）** 或 **花费（Spend）** 的数量。App 提供完整交换的报价。**路径详情（Route details）** 显示两次交换、数量和每一步的资金池费用及协议费用。学校继续之前，会检查最低收到数量和报价到期时间。

### 6. 持有人执行路由交换

学校选择 **确认兑换（Confirm exchange）** 并授权完整路线。成功后，收据会显示两次资金池交换、交换数量和费用。

如果某一步失败，两次资金池交换会一起回滚；第一次不会在没有第二次的情况下保持结算。软件如何构建和执行这笔交易，见[路由参考](https://software.cosmolocal.credit/contracts/routing)（英文）。

学校现在持有餐食代金券。链上交换属于 **交换结算**，使学校取得餐食代金券条款所述的请求权；它不能证明厨房已经提供餐食。

### 7. 持有人出示代金券

在当前 App 中，选择 **“兑付（Redeem）”** 会打开普通发送流程，并预填代币所有者的地址。把代金券发回去属于向发行方出示，但本身不能证明厨房已经提供餐食。

学校按照厨房的预约或联系流程操作。厨房确认出示，并按照公布条款提供承诺的餐食。

### 8. 发行方记录履行和解除

提供餐食后，厨房记录已经履行的单位，使其不能被重复出示。根据公布的流程，这可能包括接收、销毁、取消或以其他方式停用退回的代金券。

如果厨房不履行承诺，持有人可以使用发行方公布的投诉或补救流程，以及适用法律提供的任何权利。仅仅因为 App 找到路线或资金池支持交换，GEF 和两个资金池管理者都不会因此成为兑换方。

**“申请停用（Request retirement）”** 是不同的操作：当前所有者请求管理员停用代金券。请求待处理期间，代金券仍保持活跃；请求可以获批、被拒绝或被取消。获批后，代金券会从活跃目录中移除，但不会删除合约、余额、历史或未履行的义务。这不是履行、解除、销毁或取消。

## 责任一览

- **发行方：** 说明并履行代金券承诺，并记录解除。
- **发布需求的人：** 说明一项需要，但不会因此自动接受某张代金券或某条路线。
- **资金池管理者：** 分别公布和管理各资金池的规则、汇率、费用、限额、控制权以及明确承担的任何担保。
- **持有人：** 审查发行方、代金券条款、资金池、路线报价、费用、钱包授权和适用法律。
- **CLC App 和 CLC Core：** 发现可能路线并报价，准备和 relay 已签名批次，并对技术结算记录分组；它们不能证明发行方已经履行。
- **技术控制者：** 只行使分配给自己的合约、依赖项、升级、目录、路由服务或费用权限。
- **GEF：** 按照[服务条款](/zh/governance/terms)运营 CLC App 和支持基础设施；它不会自动承担上述其他角色。

## 路线不可用时

如果库存不足、资金池上限会被超过、代金券未获准入、代币或 quoter 不受支持、钱包没有足够输入、路线数据过时或最终批次模拟失败，App 可能找不到路线，报价也可能失败。随着资金池状态变化，报价还可能在提交前到期或失效。

这一结果不会改变需求、商品或服务项目，也不会改变发行方现有的代金券义务。参与者可以刷新路线、选择较小数量、使用另一张符合条件的输入代金券，或等待资金池条件改变。

## 未来的信用安排

未来，某个资金池或其他责任方可以另行提供可偿还垫款、担保交易或其他信用产品。此类产品需要另行提供补充条款和交易条款，明确当事方、金额、到期日、费用或利息、担保物处理、转让、违约、补救和解除证据。

普通发送、资金池存款、直接或路由资金池交换、代金券出示、履行或解除，本身不会产生这些义务。
