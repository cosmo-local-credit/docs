# 代金券实际示例

本示例跟随一项商品或服务项目和一条需求，经历由两个资金池组成的路径兑换、兑付出示、履约和核销。它说明各方角色，但不承诺任何特定代金券、资金池、路径或结果一定可用。

相关定义见 [概念和术语](/zh/introduction/concepts)。

## 1. 发行方公布一项承诺

假设一家社区厨房创建了数字餐券。发行前，厨房会公布持有人作出知情决定所需的信息：

- 厨房的身份和联系方式；
- 一张代金券代表的餐食或其他商品或服务项目；
- 供应量、单位、标示价值以及厨房的履约能力；
- 可以出示代金券的地点和时间；
- 到期日、预约流程、费用、税费或转让限制；以及
- 兑付出示、履约、投诉、退款、替代方案和其他补救措施如何运作。

厨房是发行方。它必须确保这些信息准确，不得超出合理能力发行代金券，并按照持有人取得代金券时适用的条款履行承诺。创建代币或发布商品或服务项目，不能证明厨房具备相应能力，也不会使 GEF 成为发行方。

厨房还会发布一条**商品或服务项目**，说明可提供的餐食。代金券和商品或服务项目相互关联，但并不相同：代金券代表可兑付的承诺；商品或服务项目帮助人们发现相关商品或服务。

## 2. 参与者发布一条需求

附近一所学校持有交通代金券，并需要为一场活动准备餐食。学校发布一条**需求**，说明餐食、数量、地点、时间和联系方式。

需求只表达需要。它不会自动接受厨房的代金券、预订餐食、形成合约、授权兑换，也不承诺学校一定继续。学校仍需核查厨房、代金券条款、可用路径、报价和适用条件。

## 3. 独立的资金池管理者维护一条路径

两个独立治理的资金池把资产连接起来：

1. 一个出行资金池准入学校的交通代金券和玉米代金券；以及
2. 一个粮食安全资金池准入玉米代金券和厨房的餐券。

每位资金池管理者审核资产并公布该资金池的规则，包括：

- 谁对资金池负责；
- 现在的 `SwapPool` 所有者,代理管理员和物质依赖控制器;
- 已接受的凭证和其他支持资产;
- 汇率或报价方法;
- 代币余额上限，应用中称为**“信用额度”**；
- 池和协议费用;
- 库存和流动性提取权力;以及
- 任何单独资助的担保,储备或支持安排.

准入意味着一个池的配置规则允许使用券. 它不证明履行能力,建立现金价值,创建保险或使两个池成为一个受监管实体.

## 4. 参与者提供库存

出行资金池持有可以换取交通代金券的玉米代金券。粮食安全资金池持有可以用玉米代金券换取的餐券。参与者可能根据不同的公开安排提供了这些库存。

存款增加了可用的池库存,但它不会自动创建一个池股份,还款要求,撤回权,奖励或治理权. 任何这样的权利必须来自一个单独披露的安排.

## 5. 应用发现路径并生成报价

学校的钱包打开**可存入**视图并选择餐券。CLC Core 估算一条可能的路径：

`transport voucher → mobility Pool → maize voucher → food-security Pool → meal voucher`

这一发现结果并不保证兑换成功。每一跳都取决于当前准入、资金池代币余额上限、可用库存、报价和费用配置、受支持的代币行为以及服务数据是否新鲜。

学校选择希望获取或花费的金额。CLC Core 随后在同一个固定区块读取两个资金池，生成有时间限制的权威报价，并模拟整个钱包批次。应用的**路径详情**会显示两次兑换、估算金额，以及每一跳的资金池费用和协议费用。

## 6. 持有人执行路径兑换

核对最低收到金额和报价截止时间后，学校选择**确认兑换**并签署准备好的批次。应用会提交一笔同链交易，其中包含每个资金池的授权和有明确限制的兑换调用。

如果任何调用失败，整笔交易都会回滚；第一笔资金池兑换不会在第二笔失败后仍保留为已结算。成功时，学校的分组收据会显示跟踪 ID、交易哈希、两个资金池跳、已结算金额和每一跳的费用。

学校现在持有餐券。链上兑换属于**兑换结算**。它让学校获得餐券条款所描述的权利，但不能证明厨房已经提供餐食。

## 7. 持有人呈现凭证

在当前应用中，选择**兑付**会打开普通发送流程，并预先填入代币所有者地址。把代金券送回是向发行方出示的证据；这本身不能证明厨房已经提供餐食。

学校遵循厨房的预订或联系流程. 厨房会根据公布的条款, 验证菜单并提供承诺的餐点.

## 8. 发行方记录履约和核销

提供餐后,厨房记录完成的单位,所以他们不能提出两次. 根据公布的流程,这可能涉及收到,烧毁,取消或以其他方式禁用返回的优惠券.

如果厨房不履行承诺，持有人可以使用发行方公布的投诉或补救流程，以及适用法律提供的任何权利。不能仅因 App 发现了路径或资金池支持兑换，就把 GEF 或资金池管理者视为兑付责任方。

在应用中选择**“停用代金券”**是另一项操作：它会隐藏目录条目，但余额和历史记录仍会保留，管理员可以恢复上架。它不等于履约、核销、销毁或取消。

## 职责一览

- **发行方：** 说明并履行代金券承诺，记录核销。
- **需求发布者：** 说明需要，但不会自动接受代金券或路径。
- **资金池管理者：** 分别公布和管理每个资金池的规则、汇率、费用、限制、控制，以及明确承担的任何担保。
- **持有人：** 核查发行方、代金券条款、资金池、路径报价、费用、钱包授权和适用法律。
- **CLC App 和 CLC Core：** 查找可能路径并生成报价，准备和中继已签署批次，并汇总技术结算记录。它们不能证明发行方已经履约。
- **技术控制者：** 仅行使分配给他们的合约、依赖项、升级、目录、路径服务或费用权限。
- **GEF：** 按照 [服务条款](/zh/governance/terms) 运营 CLC App 和配套基础设施；它不会自动承担上述其他角色。

## 路径不可用时

应用可能找不到路径，或因以下原因无法生成报价：库存不足；会超过资金池上限；代金券未获准入；代币或报价器不受支持；钱包缺少足够输入；路径数据已过时；或最终批次模拟失败。资金池状态变化时，报价也可能在提交前过期或失效。

这一结果不会改变需求、商品或服务项目，也不会改变发行方现有的代金券义务。参与者可以刷新路径、选择较小金额、使用另一种符合条件的输入代金券，或等待资金池状态变化。

## 未来的信贷安排

未来，某个资金池或其他责任方可以另行把一项交易作为可偿还预付款、有担保交易或其他信贷产品提供。此类产品需要另行提供补充条款和交易条款，明确当事方、金额、到期日、费用或利息、抵押品处理、转让、违约、补救措施和核销证据。

普通发送、资金池存入、直接或路径资金池兑换、代金券兑付出示、履约或核销，本身都不会产生这些义务。
