# 概念和术语

Cosmo-Local Credit 将应用、开放协议、独立治理的资金池，以及代金券所代表的现实世界承诺连接起来。这些层级相互配合，但它们并不是同一件事。

本页定义整套文档所使用的术语。当应用界面使用较短或可能有歧义的名称时，其精确标签会放在引号中。

## 产品层和协议层

| 术语 | 含义 |
| --- | --- |
| **Cosmo-Local Credit (CLC)** | 产品体系：CLC App、其文档以及更广泛的承诺汇聚工作。 |
| **CLC App** | 位于 [cosmolocal.credit](https://cosmolocal.credit) 的渐进式网页应用。GEF 运营此界面及其配套服务。 |
| **承诺汇聚协议 (CPP)** | 一套可重复使用的筛选、估值、限制、交换和负责任治理模型。 |
| **Protocol v1.1.0** | [协议参考](/zh/protocol/overview) 中记录的、经验证的公开智能合约版本。 |
| **承诺资金池 ** | 一项受治理的安排，用于筛选资产、公布规则并实现交换。** 资金池**是通常使用的简称。 |
| **`SwapPool`** | 当前的协议合约，用于持有代币库存并执行直接交换。它是承诺资金池的一个技术组成部分。 |
| **拟议的 CLC 治理代币** | 白皮书中的未来治理设计。它不是当前的应用资产或 Protocol v1.1.0 资产。 |
| **拟议的 CLC 网络资金池** | 未来的网络级清算和协调设计。它与当前的 `SwapPool` 不同。 |

## 代币、代金券与商品或服务项目

**代币** 是链上余额或数字资产。代币机制可以记录供应量、转移、过期和销毁，但它本身并不承诺商品、服务、现金转换或兑付。

**代金券** 是代币或记录，发行方将它表述为可按公布条款兑付的承诺。这些条款应当明确所承诺的内容、负责方、可以出示的地点和时间、重要限制，以及履约和投诉流程。

**商品或服务项目 (Offering)** 是与代金券关联的商品或服务目录记录。发布项目不会铸造代币、证明可用性或表明已经履约。

以下是四个不同层级：

1. 代币合约和余额；
2. 代金券命名和公布条款；
3. 一条或多条商品或服务项目记录；以及
4. 发行方在现实世界中的履约。

## 负责任角色与技术控制

| 角色或权限 | 责任或权力 |
| --- | --- |
| **发行方** | 发布并履行代金券承诺。仅仅因为合约所有权发生变化，此责任不会自动转移。 |
| **持有人** | 控制代金券余额。这种控制不证明已经履约、具有现金价值或存在保证。 |
| **服务提供者** | 面向公众的角色。服务提供者发布代金券承诺时，就成为发行方。 |
| **资金池管理者** | 负责公布和管理资金池规则的个人、合作社、公共机构、联邦、多签机制、服务或其他负责任结构。 |
| **资金池所有者** | 当前拥有 `SwapPool` 所有者权限的地址，包括配置、收取费用和提取可用流动性。 |
| **代理管理员** | 可升级代理合约实现的权限。它可能与资金池所有者不同。 |
| **依赖项控制者** | 控制注册表、限制器、报价器、预言机、费用政策或协议费用控制器的所有者或写入方。 |
| **目录审核员** | 可以纠正、隐藏或恢复目录记录，而不改变链上余额的应用运营方。 |
| **费用接收方** | 接收资金池费用或协议费用的已配置地址。它不一定是资金池管理者或所有者。 |
| **支持者或流动性提供者** | 按单独披露条款注入资产的参与者。当前的 `SwapPool` 不会创建资金池份额，也不会自动赋予偿还、提取、奖励或治理权利。 |

“社区成员”是非正式的社会语言。它本身不会产生准入、所有权、治理、偿还或其他法律权利。

## 操作与生命周期

| 应用或文档术语 | 含义 |
| --- | --- |
| **创建或发布代金券** | 部署或配置代币，并发布其目录记录和条款。 |
| **发行或铸造** | 在已配置的所有者或写入方权限下创建代币余额。 |
| **发布商品或服务项目** | 在代金券下添加商品或服务记录。 |
| **发送** | 将代币余额转移到另一个地址。 |
| **“兑付”** | 在当前应用中，打开发送流程并预先填入代币所有者的地址。这会向发行方出示或退还代币；它不证明已履约。 |
| **履约** | 发行方提供承诺的商品、服务、福利或其他给付。 |
| **核销** | 记录已履约的单位，使其不能再次出示；例如，按公布条款接收、销毁、取消或以其他方式停用。 |
| **“停用代金券”** | 在应用目录中隐藏代金券。余额和历史记录仍会保留，管理员可以恢复上架。这不是销毁或取消。 |
| **资金池存入或出资** | 将资产转入 `SwapPool`。仅当单独披露时，才存在偿还、提取、奖励或治理权利。 |
| **资金池交换** | 通过一个 `SwapPool` 将一种受支持资产换成另一种。这不是发行方履约，也不会自动构成贷款。 |
| **资金池流动性提取** | 资金池所有者将可用库存转移到选定地址。 |
| **费用收取** | 已配置的接收方收取累积的资金池费用。 |

**交换结算 ** 是完成资金池交换所需的链上转移和费用记账。** 兑付出示 **、** 履约 **和** 核销**则属于单独的现实世界代金券生命周期。

## 市场、价值、限制与费用

应用中的 **市场** 是用于发现代金券、资金池、商品或服务项目和公开信息的目录。上架不会自动构成交换场所、卖方关系、认可、估值或保证。

请区分以下价值术语：

- **商品或服务项目价格：** 上架商品或服务所要求的金额；
- **代金券标明价值：** 发行方在公布条款中表述的价值；
- **资金池汇率或报价：** 由资金池已配置报价器产生的交易参数；
- **预言机参考：** 已配置估值模块所使用的外部数据；以及
- **兑付条款：** 发行方承诺在何种条件下提供什么。

应用标签 **“信用额度”** 指资金池已配置的代币余额上限，即存入后资金池可持有的该代币最大数量。它不是个人信用额度、发行方能力检查或兑付保证。白皮书中拟议的滚动限制、账户限制和网络范围限制是不同机制。

当前的 Protocol v1.1.0 可收取 **资金池费用 ** 以及额外的 ** 协议费用 **。白皮书中的拟议模型另行描述从资金池费用中提取的未来 ** 网络分成**，以及可能的路由费用或服务费用。说明当前收费或计算未来收入时，不得混合这些模型。

## 保护与证据

筛选、纳入注册表、限制、储备、应用可见性或区块链交易，都不会自动构成认可、发行方能力、履约、保证或保险。

任何保护措施都应明确义务方、承保事件、资金、上限、除外责任、期限、证据和申请流程。链上记录可以显示地址、资产、金额、时间戳和合约事件。发行方履约、满意度、治理讨论和社会影响需要单独的披露、报告、证明或其他证据。

## 状态术语

- **当前：** 已在本文档描述的 CLC App 或 Protocol v1.1.0 中验证。
- **取决于部署：** 仅在特定部署、资金池、提供方、司法管辖区或公布政策启用时才可用。
- **历史：** 来自早期 Sarafu Network 服务的证据或功能。
- **拟议：** 未表述为已部署的设计或路线图机制。
