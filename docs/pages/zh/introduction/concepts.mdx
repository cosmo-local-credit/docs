# 概念与词汇

Cosmo-Local Credit 把提供商品或服务的人、需要这些商品或服务的人，以及支持代金券交换的独立治理承诺资金池连接起来。本页先介绍参与者会看到的词语，再说明其背后的技术层面。

如果 App 界面使用了较短或可能有歧义的名称，下文会用引号标出准确的界面标签。

## 日常用语

| 术语 | 通俗解释 |
| --- | --- |
| **代金券（Voucher）** | 一项可以转让的承诺，很像礼品卡。发行方按照公布的条款，承诺提供指定的商品、服务、权益或其他履行。 |
| **发行方（Issuer）** | 创建代金券，并继续对其承诺负责的个人或组织。 |
| **商品或服务项目（Offering）** | 描述与代金券相关商品或服务的目录记录。它帮助人们发现相关内容，但不能证明有货或已经履行。 |
| **需求（Want）** | 参与者公开说明自己正在寻找什么。它本身不会接受商品或服务项目、预留商品、授权交换或产生义务。 |
| **市场（Market）** | App 中用于发现代金券、资金池、商品或服务项目、需求及其他公开信息的目录。它本身并不自动成为交换场所、卖方、认可或担保。 |
| **承诺资金池（Commitment Pool）** | 一项受治理的安排：筛选受支持的代金券、公布交换规则、持有库存并支持交换。日常可以简称为 **资金池（Pool）**。 |
| **资金池管理者（Pool Steward）** | 公布和管理资金池规则并对其负责的个人、合作社、公共机构、联合会、多签、服务或其他结构。 |
| **持有人（Holder）** | 控制某项代金券余额的参与者。持有代金券不能证明已经履行、具有现金价值或受到担保。 |
| **钱包（Wallet）** | 用于授权代币转账和资金池交换的账户和凭据。 |

“社区成员”是非正式的社群用语，本身不会产生准入、所有权、治理、还款或其他法律权利。

## 发现并联系参与者

市场帮助人们查找代金券、商品或服务项目、需求和资金池。列入目录只表示 App 可以显示该记录；它不能证明信息准确、库存可用或交易一定成功。

参与者可以发布需求，并通过可用的联系或消息功能联系其他参与者。联系请求、消息、预约讨论或对需求的回应，本身不会：

- 接受代金券或商品或服务项目；
- 授权转账或资金池交换；
- 证明已交付或对方满意；
- 履行或解除代金券；或
- 使 GEF 成为参与者协议的一方。

评价是关于代金券或资金池的公开反馈。它不同于非公开的资格证据、运营方尽职调查、担保或已经履行的认定。

## 代金券、代币和商品或服务项目

**代币（token）** 是链上余额或数字资产。代币机制可以记录供应量、转账、到期和销毁，但本身不会承诺商品、服务、现金兑换或赎回。

**代金券** 是发行方按照公布条款表示为可兑换承诺的代币或记录。这些条款应说明承诺内容、责任方、可在何时何地出示、重要限制，以及履行和投诉流程。

**商品或服务项目（Offering）** 是与代金券相关商品或服务的目录记录。在一般文字中，“提供”只是指参与者提出的内容；**Offering** 是 App 中特定记录的名称。

应把以下四个层面分开：

1. 代币合约和余额；
2. 代币作为代金券的标识和公布条款；
3. 一项或多项商品或服务项目记录；以及
4. 发行方在现实世界中的履行。

## 责任角色与技术控制

| 角色或权限 | 责任或权力 |
| --- | --- |
| **发行方** | 公布并履行代金券承诺。仅仅改变合约所有权，不会自动转移这项责任。 |
| **资金池管理者** | 公布和管理资金池规则，并对资金池明确宣传的任何担保负责。 |
| **资金池所有者** | 当前拥有 `SwapPool` 所有者权限的地址，包括配置、收取费用和提取可用流动性的权限。 |
| **多签签名人** | 共同使用分配给多签钱包的技术权限。更改签名人或门槛，不会自动转移发行方责任、管理者问责或法律所有权。 |
| **代理管理员** | 可以升级代理合约的实现。该角色可能不同于资金池所有者。 |
| **依赖项控制者** | 控制 registry、limiter、quoter、oracle、费用政策或协议费用控制器。 |
| **目录管理员** | 可以纠正、隐藏、停用或恢复目录记录，但不会删除合约、余额或链上历史。 |
| **费用接收方** | 接收配置的资金池费用或协议费用，不一定是资金池管理者或所有者。 |
| **支持者或流动性提供者** | 按照另行披露的条款提供资产。当前 `SwapPool` 不会自动产生资金池份额、还款权、提款权、奖励或治理权。 |

## 操作与生命周期

| App 或文档术语 | 含义 |
| --- | --- |
| **创建或发布代金券** | 部署或配置代币，并公布其目录记录和条款。 |
| **发行或铸造** | 在配置的所有者或写入者权限下创建代币余额。 |
| **发布商品或服务项目** | 在代金券下添加商品或服务记录。 |
| **发布需求** | 说明一项需要，以便发现和联系；本身不会创建交易。 |
| **发送（Send）** | 将代币余额转移到另一个地址。 |
| **“兑付（Redeem）”** | 打开发送流程并预填代币所有者的地址。这属于兑付出示，不能证明已经履行。 |
| **履行（Fulfill）** | 发行方提供承诺的商品、服务、权益或其他履行。 |
| **解除（Discharge）** | 记录已经履行的单位，使其不能再次出示，例如按照公布条款接收、销毁、取消或以其他方式停用。 |
| **“申请停用（Request retirement）”** | 当前所有者请求管理员停用代金券或资金池。请求待处理期间资源仍保持活跃；请求可以获批、被拒绝或被取消。 |
| **代金券停用** | 获批后，从活跃目录中移除代金券。合约、余额、义务和历史仍然保留；停用并不等于销毁或解除。 |
| **资金池停用** | 获批后，停止新的资金池交换和存款，同时允许可用的提款。此前的结算记录仍然保留。 |
| **资金池存款或贡献** | 将资产转移到 `SwapPool`。只有在另行披露时，才会产生还款、提款、奖励或治理权。 |
| **资金池交换** | 通过一个 `SwapPool` 交换受支持资产。这既不是发行方履行，也不会自动形成贷款。 |
| **路线发现** | 通过配置的资金池关系寻找可能的路径。发现只是估算，不是可执行承诺。 |
| **路线报价** | 根据在一个固定区块读取的资金池状态计算有时限的提案，并在签名前进行模拟。 |
| **路由交换** | 把有序的资金池交换作为一个同链钱包批次提交。在当前流程中，只要一个调用失败，所有调用都会回滚。 |
| **路由交换收据** | 把跟踪状态、交易哈希、路线各跳、已结算数量和每一跳费用归为一组。 |
| **提取资金池流动性** | 允许资金池所有者把可用库存转移到选定地址。 |
| **收取费用** | 把累计的资金池费用发送给配置的接收方。 |

用 **交换结算（swap settlement）** 表示完成资金池交换的链上转账和费用核算。用 **兑付出示（redemption presentment）**、**履行（fulfillment）** 和 **解除（discharge）** 表示彼此独立的现实世界代金券生命周期。

## 产品和协议层面

| 术语 | 含义 |
| --- | --- |
| **Cosmo-Local Credit（CLC）** | 产品体系，包括 CLC App、相关文档以及更广泛的承诺汇集工作。 |
| **CLC App** | 位于 [cosmolocal.credit](https://cosmolocal.credit) 的渐进式网页应用。GEF 运营该界面及其支持服务。 |
| **CLC Core** | 为目录、索引后的链上状态、路线发现、权威报价、relay 协调和路由交换收据提供支持的服务。它既不是智能合约，也不是资金池管理者。 |
| **承诺汇集协议（Commitment Pooling Protocol，CPP）** | 关于筛选、估值、限制、交换和责任治理的可复用模型。 |
| **Protocol v1.1.0** | [权威软件参考](https://software.cosmolocal.credit/contracts/)中记录的公开智能合约版本（英文）。 |
| **`SwapPool`** | 当前持有代币库存并执行直接交换的协议合约。它是承诺资金池的一个技术组成部分。 |
| **Solidity `SwapRouter`** | Protocol v1.1.0 中为拟议的多资金池路径提供报价的合约。它不托管资产，也不执行路线。 |
| **应用层路由流程** | App 和支持服务通过资金池寻找可能的路径、为交换报价、请求参与者授权，并报告结果。 |
| **拟议的 CLC 治理代币** | 白皮书中的未来治理设计，不是当前 App 或 Protocol v1.1.0 的资产。 |
| **拟议的 CLC 网络资金池** | 未来的网络级清算和协调设计，不等同于当前 `SwapPool`。 |

## 价值、信用、限额和费用

应区分以下价值术语：

- **商品或服务项目价格：** 列出商品或服务所要求的金额；
- **代金券标示价值：** 发行方在公布条款中表示的价值；
- **资金池汇率或报价：** 资金池配置的 quoter 生成的交易参数；
- **oracle 参考：** 配置的估值模块使用的外部数据；以及
- **兑换条款：** 发行方承诺什么，以及在什么条件下履行。

App 中的 **信用（Credit，界面标签为“可存入”）** 是指可达的承诺和交换容量，并不自动表示个人借款、贷款、发行方能力评估或担保。

**“信用额度（Credit limit）”** 标签是指资金池配置的代币余额上限，也就是存款后资金池最多可以持有的该代币数量。白皮书中拟议的滚动限额、账户限额和全网络限额是不同机制。

Protocol v1.1.0 可以对每次资金池交换收取 **资金池费用** 和一项额外的 **协议费用**。路由交换会逐跳列出这两种费用。当前 App 不收取单独的路由服务费。拟议白皮书模型另行描述未来的网络抽成和可能的服务费用。

## 路线与流动性

**路线** 是通过一个或多个独立治理资金池的有序路径。**路线深度** 是该路径中的资金池交换次数。

并非每张代金券、每个资金池或每种钱包都符合路由资格。出现在资金池中，不会使代金券自动通过所有路线可用。[软件路由参考](https://software.cosmolocal.credit/contracts/routing)以英文维护当前资格规则和配置。

**可用流动性** 是资金池按照当前规则、限额和费用能够提供的库存。资金池之间存在连接，不能证明您想要的数量可用。请审核最终报价；资金池条件变化时，报价可能到期或失效。

当前路线执行由钱包发起并发生在同一条链上。它不会合并治理、自动重新平衡资金池库存、在多方之间清算义务或证明履行。跨链 HTLC 或托管路由、自动再平衡和批量净额结算仍属于拟议功能或取决于具体部署。

## 保护与证据

筛选、纳入 registry、限额、储备、App 可见性、评价或区块链交易，本身都不能证明认可、发行方能力、履行、担保或保险。

任何保护安排都应说明义务方、承保事件、资金来源、上限、除外事项、期限、证据和索赔流程。链上记录可以显示地址、资产、金额、时间戳和合约事件。发行方表现、满意程度、治理讨论和社会影响需要单独的证据。
