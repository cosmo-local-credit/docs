# 协议网络架构

多个独立治理的资金池可以把您持有的代金券连接到想要的代金券。每个资金池按照自己的规则，使用可用库存完成交换中的一步。

[CLC 软件路由参考](https://software.cosmolocal.credit/contracts/routing)是路线发现、资格、执行和服务接口的权威来源。软件文档目前提供英文版本。本页说明参与者的操作流程和责任。

## 生产路径发现与执行

在 App 的 **可存入（Credit）** 视图中，选择想要 **获取（Get）** 或 **花费（Spend）** 的代金券。例如，某条路线可以通过两个不同的资金池，把交通代金券换成食品代金券。

找到连接并不保证可以交换。受支持的代金券、资金池限额、可用库存、费用、钱包兼容性和服务可用性，都必须允许所请求的数量。

### 权威报价

确认前请查看 **路径详情（Route details）**：您支付什么、收到什么、每个参与的资金池、费用、最低收到数量和报价到期时间。估算帮助您探索选项；报价才是您授权的交易提案。报价到期或资金池条件改变时，应重新获取报价。

[路由参考](https://software.cosmolocal.credit/contracts/routing)和[服务配置](https://software.cosmolocal.credit/core-api/configuration#credit-router)维护技术资格规则和报价设置。

### 已签署的原子批次

您审核并授权完整交换。当前路线要么整体成功，要么在某一步失败时，把所有资金池交换一起回滚。这样可避免仅完成部分路线，但不能保证之后一定交付商品或服务。

交易构建和执行方法，见[执行路线](https://software.cosmolocal.credit/contracts/routing#execute-a-route)。

### Solidity `SwapRouter` 与费用

仅提供报价的 Solidity `SwapRouter` 与 App 的交换流程是不同的软件组件。二者的关系见[路由](https://software.cosmolocal.credit/contracts/routing)。

对参与者而言，重要的是检查完整报价。每个资金池都可能收费。共享路线不会合并资金池，也不会使某个管理者对另一个资金池负责。

### 收据与失败状态

提交后，请检查交换是待处理、已确认还是失败，并保留收据。找不到路线时，可以尝试刷新、减少数量或选择另一种受支持的输入代金券。

交换失败不会改变发行方已有的承诺。交换成功会记录余额变化；履行和解除仍按照发行方条款处理。请参阅[实用示例](/zh/introduction/example)。

开发者可在 [CLC Core API 参考](https://software.cosmolocal.credit/core-api/reference)中查阅交易和跟踪接口。

## 资金池内部结构

依赖资金池之前，请确定管理者、合约所有者、升级权限方、费用接收方，以及谁能更改重要设置。技术控制者与负有责任的管理者可能是不同的主体。

软件参考文档维护[资金池机制](https://software.cosmolocal.credit/contracts/pools)和[部署验证](https://software.cosmolocal.credit/contracts/deployments)。本文档说明[角色与词汇](/zh/introduction/concepts)、[治理责任](/zh/governance/mechanics)和[更广泛的 CPP 设计](/zh/white-paper)。
